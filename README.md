# Devex — プロジェクトスコープ定義

Devexは、AIとの対話でユーザーの要望を引き出し、**要件定義から設計・実装計画・実装手順・テストまでの開発プロセスをつなぎ、設計の一貫性と実装可能性を支援するシステム**である。

## コンセプト

- **文書を増やすことを目的にしない**。各段階の設計情報を構造化し、ID で相互に参照できるようにつなぐ(設計情報の構造化とトレーサビリティ)。
- **価値は、設計そのものの品質・一貫性・実装可能性を高めること**にある。AI がコードや文書を大量に生成することは目的にしない。
- **人間が理解・判断しながら開発できる状態を作る**。なぜこの構造なのか、責務をどこに持たせるか、どの順番で実装するか、どの変更がどこへ影響するかを人が把握できるようにする。セキュリティや非機能要件も、AI の提案に頼り切らず、ユーザー自身の判断として引き出す。
- **ポートフォリオとしての位置づけ**: 「システム設計という問題をどう捉え、AI と構造化された設計情報でどう解決しようとしたか」という、設計の思考過程を示す作品とする。

方針の詳細と今後の計画は [`appendix/devex_roadmap.md`](appendix/devex_roadmap.md) を参照。

## ステージ

| ステージ | トピック | 概要 | 目的 | 状態 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | MVP | チャットによるヒアリングと、4文書(要件定義・外部設計・内部設計・実装計画)の一括生成、プレビュー・ダウンロード、本番デプロイ | コア機能をエンドツーエンドで動かす | 完了(Phase 1〜5) |
| 2 | 機能拡張・品質向上 | 文書のバージョン履歴、プロンプトテンプレートの選択、構造化ログ・エラー追跡 | 継続して使える品質にする | 完了(Phase 6) |
| 3 | UML設計図パイプライン | UML 意味モデル(構造化データ)、自動レイアウト、React Flow での編集、承認、draw.io / SVG 出力 | 設計を文章ではなく構造として扱う土台を作る | 完了(Phase 7〜13) |
| 4 | 詳細設計モード | 機能一覧 → データフロー → データモデル → ソフトウェア構造 → 主要処理の手順 → 処理ロジック → 横断事項と実装計画を、段階ごとに承認しながら組み立てる。処理IDによる紐づけと陳腐化の検知 | 実務に合わせ、人がコーディングするのに十分な詳細設計を作る | 完了(Phase 14〜24) |
| 5 | 実装手順書 + 実装可能性チェック | 作業単位ごとの手順書(対象ファイル・責務・実装順序・使う設計・確認方法)を生成し、その過程で設計の不足・矛盾を指摘する | 設計を実際の開発作業へ落とし込み、実装できない設計を表に出す | 着手(Phase 25〜32 予定) |
| 6 | ヒアリング改良 + 上流の構造化 | 観点ごとの状態と出どころの記録、非機能要求グレードに基づく観点、答えやすい問い方、要件IDの採番 | 聞き漏れと設計後の要件変更を減らし、要件から作業単位まで追跡できるようにする | 予定 |
| 7 | 変更影響分析・変更管理 | ID でつないだ要素のグラフから、変更の影響範囲を示す。陳腐化を要素単位で管理する | 設計を変更に強くする | 予定 |
| 8 | AI設計レビュー + テスト設計 | 生成と分けたレビュー、レビュー結果からの再ヒアリング、テスト観点・テストケースの生成、生成の質の評価 | 設計を成り立たせ、要件からテストまでの追跡を完成させる | 予定 |
| 9 | 設計・実装の整合性検証 | 実際のコードと設計のずれを検出する(まず Devex 自身で試す) | 開発中・開発後も使える設計管理の基盤にする | 将来 |
| 10 | GitHub / CI/CD・運用 | Pull Request と設計IDの関連付け、CI での設計整合性チェック | 設計情報を開発ライフサイクルに組み込む | 将来 |

完了済みのステージの詳細は [実装計画書](docs/implementation_plan.md) 4.1節を参照。ステージ5は実装計画書 4.1節に書き写した(Phase 25)。ステージ6以降は、各ステージの着手時に書き写す。

## 詳細仕様

詳細仕様は以下の4ドキュメントに分割している(Devex自身が生成する4種のドキュメントと同じ構成 ── [外部設計書](docs/external_design.md) 2.3節 SCR-005参照)。

| ドキュメント | 内容 |
| :--- | :--- |
| [要件定義書](docs/requirements.md) | 目的・背景、ターゲットユーザー、In Scope/Out of Scope、機能要件(MoSCoW)、非機能要件、制約条件 |
| [外部設計書](docs/external_design.md) | システム構成、画面一覧・遷移、UI/UX仕様、外部API連携、データ入出力仕様 |
| [内部設計書](docs/internal_design.md) | 技術スタック・アーキテクチャ方針、データモデル、バックエンド処理・モジュール設計、エラーハンドリング |
| [実装計画書](docs/implementation_plan.md) | 開発ステージ分割・マイルストーン、WBS、開発環境・CI/CD、想定リスクと対策 |
