# ヒアリングの側面とゆらぎの数え方(Phase 47)

[Phase 47](../../textbook/Phase-47/Phase-47-introduction.md) で足した観点(データの保全・データの保持・削除・ログ・不正利用)が聞けるか、また判定のゆらぎ(自由回答が「採用」になる)がどれだけ出るかを、ヒアリングの回ごとに数える道具。測定そのものは Phase 49(効果測定)で行う。

## 実行

```bash
python3 appendix/stage7-hearing/tally.py <実行フォルダ> [<実行フォルダ> ...] [--out results.md]
```

- 実行フォルダは [`stage6-effect/drive.py`](../stage6-effect/README.md) が書き出すもの(`metrics.json` と `chat_history.txt`。`chat_history_before_generation.txt` があればそちらを読む)。
- フォルダ名の先頭(`detailed`・`simple`)をモードとみなす。
- 外部の API・LLM は呼ばない。標準ライブラリだけで動く。

## 数えるもの

| 列 | 数え方 |
|---|---|
| 発言 | 生成の前の利用者の発言(`--- user`)の数。生成の後(`--- others` 以降)は数えない |
| L1〜L14 | ペルソナ([`persona.md`](../stage6-baseline/persona.md))の潜在の事実を聞く観点が、利用者の発言を根拠に未決以外(決定・採用・対象外)になったか。`—` はその版に観点が無い(ステージ6の回の L2・L5・L6・L14) |
| 自由回答の採用 | 状態が「採用」なのに、根拠の発言にその観点のカードの回答(`【ラベル】選んだ選択肢` の行)が無いもの。判定のゆらぎの指標 |

観点の**状態**で数える。中身が事実と合うか(例: ステージ6の1回目の簡易で、環境の観点に技術スタックが入った)は、これまでどおり人が読んで確かめる。

## ステージ6の回(ゆらぎのベースライン)

[`stage6-runs.md`](./stage6-runs.md)。`stage6-effect` の4回(詳細・簡易 × 1回目・2回目)を数えたもの。側面の4つは観点が無いので数えない。自由回答の採用は、詳細 0〜3・簡易 2〜4。2回目の詳細の3件(1日の流れ・例外・運用)は、[Phase 39-3](../../textbook/Phase-39/Phase-39-3.md) の記述と一致する。1回目と2回目では本体の版が違う(39-2 の直しの前と後)ので、この幅は同じ版のゆらぎではない。

## Phase 49 での流し方(Phase 47 で決めた)

- 同じ版の本体で、**詳細・簡易を3回ずつ**ヒアリングする(ヒアリングだけ。生成は1回目だけでよい)。
- ペルソナと規則は [`stage6-effect`](../stage6-effect/README.md) の「規則の差分」と同じ。ただし観点が4つ増えたため、発言の上限を20回から **24回** に上げる。
- 回ごとのフォルダ(例: `appendix/stage7-effect/hearing/detailed-1`)に `drive.py points`・`metrics` の出力と `chat_history.txt` を置き、このスクリプトで数える。幅(最小〜最大)で判断し、1回の結果では判断しない。
