- **[中程度 / 不整合]** 外部設計書の API 一覧 / 内部設計書の DF-2
  - 問題: 外部設計書の `POST /api/v1/auth/login` の説明ではトークンを本体の JSON で返しフロントエンドが localStorage に保存すると記載されていますが、要件定義書の FR-002 では「リフレッシュトークンは14日でHttpOnly Cookieに保存する」と規定されています。
  - 理由: 要件定義書のセキュリティ要件（HttpOnly Cookie）と外部設計書のAPI応答・保存方式の仕様に矛盾があるためです。
  - 改善案: `POST /api/v1/auth/login` の仕様を修正し、アクセストークンおよびリフレッシュトークンを HttpOnly Cookie で設定するように変更するか、要件との整合性を合わせてください。

- **[中程度 / 設計]** 外部設計書の API 一覧 / 内部設計書のデータモデル（projects テーブル）
  - 問題: 参考資料のアップロードを行う `POST /api/v1/projects` が `files` を受け付ける設計になっていますが、データベースの `projects` テーブルには `reference_file_paths (TEXT[])` が定義されており、アップロードされたファイルの実体や保存処理（ストレージやファイル名管理）のフローが定義されていません。
  - 理由: アップロードされたファイルがどのように保存され、どのパスとしてテーブルに格納されるかのデータ処理の結び付きが抜けているためです。
  - 改善案: ファイルの保存先ディレクトリやストレージへの格納処理をバックエンド処理（DF-3など）に明記し、ファイルパスの生成方法を定義してください。

- **[中程度 / 設計]** 内部設計書のテーブル定義（users テーブル）
  - 問題: `users` テーブルの `password` カラムの説明に「ログイン時にそのまま照合する」と記載されています。
  - 理由: パスワードをハッシュ化せずに平文で保存・照合するセキュリティ上の重大な問題（要件定義書の FR-002 およびバックエンドの core/security.py の「パスワードのハッシュ化」との矛盾）があるためです。
  - 改善案: `users` テーブルの `password` カラムの説明をパスワードハッシュ（salted hash）を格納する旨に修正してください。
