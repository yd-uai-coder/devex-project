# 2. 外部設計書

## 2.1 システム構成概要

本システムは、ブラウザからNext.js (Tamagui) によるWebフロントエンドを介し、リバースプロキシ (nginx) を経由してFastAPIバックエンドと通信するアーキテクチャである。\n\n```\n+------------------+       +--------------------------------------------+\n|   Web Browser    | <---> |                 Cloud VPS                  |\n| (Next.js/Tamagui)|       |  +-------------+       +-----------------+ |\n+------------------+       |  |    nginx    | <---> | FastAPI Backend | |\n                           |  +-------------+       +--------+--------+ |\n                           |                                 |          |\n                           |        +------------------------+          |\n                           |        |                |                  |\n                           |  +-----v------+  +------v-------+          |\n                           |  | PostgreSQL |  | Redis (Cache/|          |\n                           |  | (Main DB)  |  | Rate Limit)  |          |\n                           |  +------------+  +--------------+          |\n                           +--------------------------------------------+\n                                                     |\n                                                     v\n                                          +----------------------+\n                                          | Google Gemini API    |\n                                          | (Gemini Flash-Lite)  |\n                                          +----------------------+\n```

## 2.3 主要画面のUI/UX仕様

### SCR-001: 新規登録画面

- 入力項目: メールアドレス、パスワード、パスワード確認\n- 表示項目: サービスロゴ、ログイン画面への導線リンク、入力エラーメッセージ\n- 操作ボタン: 「アカウント作成」ボタン\n- アクション: 入力バリデーション実行後、登録APIを呼び出し、成功時はプロジェクト一覧画面へ遷移

### SCR-002: ログイン画面

- 入力項目: メールアドレス、パスワード\n- 表示項目: サービスロゴ、新規登録画面への導線リンク、認証エラーメッセージ（試行制限警告含む）\n- 操作ボタン: 「ログイン」ボタン\n- アクション: 認証API呼び出し、JWT取得・Cookie保存後、プロジェクト一覧画面へ遷移

### SCR-003: プロジェクト一覧・新規作成画面

- 表示項目: ユーザー情報表示バー、過去に作成したプロジェクト一覧（プロジェクト名・作成日時・ステータス）、ログアウトボタン\n- 入力項目(モーダルまたは展開エリア): 新規プロジェクト名、参考資料ファイル添付フォーム（txt/md/pdf、最大3ファイルまでドラッグ＆ドロップまたはファイル選択）\n- 操作ボタン: 「新規プロジェクト作成」ボタン、各プロジェクトカード（選択でヒアリング画面または設計書画面へ遷移）\n- アクション: ファイル拡張子・件数検証、新規プロジェクト登録API呼び出し後にSCR-004へ遷移

### SCR-004: 要件ヒアリングチャット画面

- 表示項目: プロジェクト名ヘッダー、参考資料プレビュー領域、チャットタイムライン（ユーザーメッセージ／AI質問の吹き出し）、文字数カウンター、エラー通知トースト（再送ボタン付き）、生成処理中インジケーター\n- 入力項目: メッセージ入力テキストエリア（数千文字上限、空送信抑止）\n- 操作ボタン: 「送信」ボタン、「設計書を一括生成する」ボタン、プロジェクト一覧へ戻るリンク\n- アクション: メッセージ送信API実行（初文ストリーミング表示）、設計書一括生成APIのトリガー（生成中は入力欄とボタンを非活性化し、完了時にSCR-005へ自動遷移）

### SCR-005: 設計書プレビュー・自己診断画面

- 表示項目: ドキュメント種別タブ（要件定義書／外部設計書／内部設計書／実装計画書）、AI自己診断パネル（「最重要」「中程度」「軽微」の3段階バッジと不足点詳細リスト）、Markdownプレビュー表示エリア、生成失敗時の再生成案内バナー\n- 操作ボタン: 「Markdownをコピー」ボタン、「Markdownをダウンロード」ボタン、「再生成する」ボタン（失敗時または再試行時）、「チャットに戻る」ボタン\n- アクション: クリップボードへのMarkdownコピー、単体Markdownファイルのローカルダウンロード、再生成API呼び出し

## 2.5 データ入出力仕様

### 1. 参考資料アップロード仕様 (FR-002)\n- 受付ファイル形式: テキスト (`.txt`)、Markdown (`.md`)、PDF (`.pdf`)\n- 受付件数: 1プロジェクトにつき最大3ファイル\n- バリデーション: ファイル拡張子およびMIMEタイプの厳格チェック。サイズ超過および不正拡張子はリクエスト時に400エラーで拒否。\n\n### 2. チャット入出力仕様 (FR-003, FR-008)\n- 入力テキスト: 最大4,000文字。空白文字のみの送信はバリデーションにより抑止。\n- 出力テキスト: ストリーミングテキスト（SSE）形式によるレスポンス。\n\n### 3. 設計書エクスポート仕様 (FR-006)\n- 出力形式: Markdownファイル (`.md`)\n- 文字コード: UTF-8\n- 提供形態: クリップボードへのプレーンテキストコピー、ブラウザ経由の個別ファイルダウンロード
