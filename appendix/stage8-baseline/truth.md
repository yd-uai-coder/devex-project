# 正解表(レビューを流す前に書いた)

2026-10-13、どのレビューの方式も流す前に書いた。測定の後でこの表は書き換えない。レビューが挙げた、表に無い正しい指摘は、`results.md` の「表に無い正しい指摘」に分けて数える。

- 重要度: 最重要 = 実装に着手できない・安全を損なう / 中程度 = 実装はできるが手戻りになる / 軽微 = 細部。
- 原因: **ヒアリング** = 聞けていない・聞き方が浅い(再ヒアリングで直す)/ **設計** = 1つの文書の中の誤り・抜け / **不整合** = 文書どうし・要件と設計の食い違い。
- L0: 今の決定的な検証(`app/documents/*/validation.py`)でも出るもの。○ は LLM のレビューが当てても「新しく見つけた」とは数えない(別に数える)。
- 当たりの目安: 対象の要素と問題の中身の両方が合っていれば当たり。対象だけ・一般論(「セキュリティを強化すべき」など)は当たりにしない。
