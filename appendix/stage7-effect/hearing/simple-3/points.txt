scale=public sufficient=True
scale 必須 adopted 誰でも登録できるサービスにする
purpose 必須 decided システム開発初期フェーズにおけるドキュメント作成の工数と属人化を減らすため、対話から4種の設計書を自動生成する。
users 必須 adopted SE、ITコンサルタント、PM、個人開発者、スタートアップ創業者などが、新規プロジェクトの立ち上げやクライアントヒアリング時に開く。
daily_flow 必須 decided クライアントとの打ち合わせ後に30分ほどでヒアリングを済ませ、その日のうちに生成されたドラフトを見直して共有する。
core 必須 decided 対話型チャットによるヒアリングと4種の設計書の一括生成、生成後の自己診断、プレビュー・コピー・ダウンロード、初期の参考資料読み込み、PostgreSQLへの保存機能。
scope 必須 not_applicable 
exceptions 必須 decided APIの失敗時は理由を表示してメッセージを保存せずに再送を促し、生成失敗時は再生成を行えるようにする。
future 必須 decided テンプレートの選択、版の履歴の画面、設計図(UML)を後で追加する。
tech 必須 decided フロントエンドは Next.js (App Router) + Tamagui、バックエンドは FastAPI + LangChain・LangGraph (Python 3.13)、データベースは PostgreSQL、Redis、サーバーは VPS (Docker Compose + nginx)、CI/CDは GitHub Actions、AIは Gemini Flash-Lite を使用する。
schedule 任意 open 
availability 必須 decided 半日程度の停止なら許容され、夜間の保守の停止も問題ない。
backup 必須 decided DBを毎日バックアップし7日分を残し、VPSの外にもコピーする。
performance 必須 decided 同時に使うのは数人〜十数人で、チャットの最初の文字が数秒で出ること、4文書の生成は数分まで待つことが許容される。
operability 必須 decided エラーの追跡と死活監視は必要だが、MVPの後で導入する。
data_retention 必須 decided プロジェクトやアカウントの削除機能はMVPでは不要とする。
migration 必須 adopted 移行するデータや仕組みはない
security 必須 decided 本人以外が他人のプロジェクトを見られないよう分離し、ログインはメールアドレスとパスワードによるJWT認証(アクセス30分、リフレッシュ14日、リフレッシュはHttpOnly Cookie)とする。
logging 必須 adopted 機密保持のため、チャットや入力の内容は一切ログに残さない
abuse 必須 decided ログインの総当たりや登録の大量作成を防ぎ、チャットと生成にも回数の上限を設ける。
environment 必須 decided PCの最新のChrome、Edge、Firefox、Safariで利用し、スマートフォンは閲覧ができれば十分とする。
