システム概要：Devex: AI との対話型チャットでユーザーのアイデアや要望をヒアリングし、「要件定義」「外部設計」「内部設計」「実装計画」の4種の Markdown 設計書を自動生成する Web アプリ。システム開発の初期フェーズで、ドキュメント作成の工数と属人化を減らしたい。

実現したい事：- チャットでヒアリングし、4種の設計書を一括生成する(MVP)
- 生成後に AI が各文書の不足点を3段階(最重要/中程度/軽微)で自己診断して提示する
- 生成した Markdown をプレビュー・コピー・ダウンロードできる
- 参考資料(txt/md/pdf、最大3件)を初期入力で読み込める
- ユーザー・チャット履歴・生成文書を PostgreSQL に保存する

ヒアリングの内容をまとめました。

- 規模: 公開サービス
- 目的・課題: システム開発の初期フェーズにおけるドキュメント作成の工数と、属人化による質のばらつきを減らしたい
- 利用者と使う場面: SE・ITコンサルタント・PMや個人開発者・スタートアップの創業者が新規プロジェクト立ち上げやクライアントヒアリング時に使う
- 利用者の1日の流れ: クライアントとの打ち合わせの後に30分ほどでヒアリングを済ませ、その日のうちに生成されたドラフトを見直して共有する
- コア機能: チャットヒアリングによる4種の設計書自動生成、不足点の3段階診断、プレビュー・コピー・ダウンロード、参考資料読み込み、PostgreSQLへのデータ保存
- MVP の範囲: 最初の版ではコードの自動生成、Jira・Notion連携、マルチテナントの権限管理、音声入力、複数人の同時編集を作らない
- 例外の場面: AIの応答が途中で失敗した場合は理由を出して送ったメッセージを保存せずに再送を促し、生成失敗時は再生成できるようにする。チャットは数千文字までで空送信は不可とする
- 将来の拡張: テンプレートの選択、版の履歴の画面、設計図(UML)を後で追加する
- 技術スタック・環境の制約: フロントエンドは Next.js(App Router)+ Tamagui、バックエンドは FastAPI + LangChain・LangGraph(Python 3.13)、DB は PostgreSQL、Redis(レート制限・トークン失効)。VPS に Docker Compose と nginx で置き、GitHub Actions で main への push から自動デプロイする。LLM は Gemini Flash-Lite(無料枠)
- 可用性: 止まっても半日なら困らず、夜間の保守の停止はかまわない
- 可用性(データの保全): DBを毎日バックアップし7日分を残し、VPSの外にもコピーする
- 性能・拡張性: 同時に使うのは数人〜十数人で、チャットの最初の文字が数秒で出ればよく、4文書の生成は数分まで待てる
- 運用・保守性: エラーの追跡と死活監視はMVPの後で行う
- 運用・保守性(データの保持・削除): プロジェクトの削除やアカウント退会機能はMVPでは不要とする
- 移行性: 移すものは無い(すべて新しく始める)
- セキュリティ: 本人以外が他人のプロジェクトを見られないようにし、メールアドレスとパスワードによるJWT認証(アクセス30分・リフレッシュ14日、リフレッシュはHttpOnly Cookie)を用いる
- セキュリティ(ログ): 機密情報を避けてシステムのエラーや動作履歴だけを残す
- セキュリティ(不正利用): ログインの総当たり、登録の大量作成、チャットと生成の回数上限を設けて不正利用を防ぐ
- システム環境・エコロジー: PCの最新のChrome・Edge・Firefox・Safariで使い、スマホは読めれば十分とする
