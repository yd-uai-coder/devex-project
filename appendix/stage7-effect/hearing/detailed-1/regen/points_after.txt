scale=public sufficient=True
scale 必須 adopted 誰でも登録できるサービスとして展開する
purpose 必須 decided システム開発の初期フェーズにおけるドキュメント作成の工数と、属人化による質のばらつきを減らしたい
users 必須 decided SE・ITコンサルタント・PMや個人開発者・スタートアップの創業者が新規プロジェクト立ち上げやクライアントヒアリング時に使う
daily_flow 必須 decided クライアントとの打ち合わせの後に30分ほどでヒアリングを済ませ、その日のうちに生成されたドラフトを見直して共有する
core 必須 decided チャットヒアリングによる4種の設計書自動生成、不足点の3段階診断、プレビュー・コピー・ダウンロード、参考資料読み込み(最大5件)、PostgreSQLへのデータ保存
scope 必須 decided 最初の版ではコードの自動生成、Jira・Notion連携、マルチテナントの権限管理、音声入力、複数人の同時編集を作らない
exceptions 必須 decided AIの応答が途中で失敗した場合は理由を出して送ったメッセージを保存せずに再送を促し、生成失敗時は再生成できるようにする。チャットは数千文字までで空送信は不可とする
future 必須 decided テンプレートの選択、版の履歴の画面、設計図(UML)を後で追加する
tech 必須 decided フロントエンドは Next.js(App Router)+ Tamagui、バックエンドは FastAPI + LangChain・LangGraph(Python 3.13)、DB は PostgreSQL、Redis(レート制限・トークン失効)。VPS に Docker Compose と nginx で置き、GitHub Actions で main への push から自動デプロイする。LLM は Gemini Flash-Lite(無料枠)
schedule 任意 open 
availability 必須 decided 止まっても半日なら困らず、夜間の保守の停止はかまわない
backup 必須 decided DBを毎日バックアップし7日分を残し、VPSの外にもコピーする
performance 必須 decided 同時に使うのは数人〜十数人で、チャットの最初の文字が数秒で出ればよく、4文書の生成は数分まで待てる
operability 必須 adopted エラーの追跡と死活監視はMVPの後で行う
data_retention 必須 decided プロジェクトの削除やアカウント退会機能はMVPでは不要とする
migration 必須 adopted 移すものは無い(すべて新しく始める)
security 必須 decided 本人以外が他人のプロジェクトを見られないようにし、メールアドレスとパスワードによるJWT認証(アクセス30分・リフレッシュ14日、リフレッシュはHttpOnly Cookie)を用いる
logging 必須 adopted 機密情報を避けてシステムのエラーや動作履歴だけを残す
abuse 必須 decided ログインの総当たり、登録の大量作成、チャットと生成の回数上限を設けて不正利用を防ぐ
environment 必須 decided PCの最新のChrome・Edge・Firefox・Safariで使い、スマホは読めれば十分とする
