## 設計レビュー
指摘 9件(最重要 1・中程度 7・軽微 1)

1. **[最重要 / ヒアリング・観点 security]** FR-001, NFR-008, POST /api/v1/projects/{id}/chat, POST /api/v1/projects/{id}/summary/approve
   - 問題: セキュリティ観点が「ログインをMVPに入れる」だけで、誰が誰のプロジェクト・文書・チャット履歴を見られるか(本人以外の閲覧・変更の可否)が決まっていない。トークンの種類・有効期限・失効条件・パスワードの扱いも未決。
   - 引用: security | AI の提案を採用 | ログインをMVPに入れる / FR-001: ユーザー登録およびログイン機能を提供する
   - 理由: 公開サービス(scale)で複数ユーザーが登録するため、他人のプロジェクトIDを指定した閲覧・操作を防ぐ認可方針が要件にない。外部設計書2.6のAPIにも所有者チェックの記載がなく設計の根拠がない。
   - 改善案: 利用者に「プロジェクトは作成者本人のみ閲覧・変更可」などの方針と、トークン有効期限・失効条件・パスワード要件を聞き直し、要件に追加する。
2. **[中程度 / ヒアリング・観点 abuse]** NFR-008
   - 問題: 回数上限・総当たり対策の具体値(回数・単位・期間・超過時の挙動)が決まっていない。
   - 引用: NFR-008: ログインの総当たり、登録の大量作成、チャットや生成の回数上限を設けて不正利用を防ぐ
   - 理由: 数値がないとレート制限の実装やAPIの429応答の設計ができない。外部設計書2.6にも429エラーが一切ない。また無料枠のGeminiの上限(CON-004)との整合も取れない。
   - 改善案: ユーザーあたり・IPあたりの回数、期間、ロック時間、超過時の表示を聞いて要件に落とし、各APIのエラーに429を追加する。
3. **[中程度 / 設計]** POST /api/v1/projects/{id}/summary/approve, SCR-004, SCR-005, FR-005, FR-006, NFR-003
   - 問題: 4文書の順次生成と自己診断は数分かかるが、承認APIは「200 OK (生成開始)」を返すだけで、進捗確認・完了通知・失敗時の再生成のAPIがない。
   - 引用: POST /api/v1/projects/{id}/summary/approve | 構造化サマリ承認と文書生成開始 | ... | 200 OK (生成開始) | 500 生成失敗 / NFR-003: 4文書生成は数分以内の待機
   - 理由: FR-009で「生成失敗時は再生成できる」とあるが、再生成API・生成状態の取得API・非同期処理の方式が外部設計にない(SCR-005に再生成ボタンはある)。
   - 改善案: 非同期ジョブとして生成状態取得API(GET)と再生成API(POST、文書単位か全体か明記)を追加し、状態(生成中・完了・失敗)と画面表示を定義する。
4. **[中程度 / 設計]** SCR-004, 修正依頼ボタン, POST /api/v1/projects/{id}/summary/approve
   - 問題: 構造化サマリの表示・生成・修正依頼に対応するAPIがない。ヒアリング完了を通知するAPIもない。
   - 引用: SCR-003: ヒアリング完了ボタン / SCR-004: 操作ボタン: 承認して文書生成へ進むボタン、修正依頼ボタン / API一覧に summary 関連は approve のみ
   - 理由: 画面操作(ヒアリング完了、サマリ取得、修正依頼)に対応するAPIがなく、FR-004の「確認して承認する」を満たせない。
   - 改善案: ヒアリング完了・サマリ取得(GET)・修正依頼のAPIを追加し、修正依頼後の遷移も定める。
5. **[中程度 / 設計]** SCR-005, FR-008, GET /api/v1/projects/{id}/documents
   - 問題: 版切り替え・再生成・ダウンロード・自己診断結果の取得が API で表現されていない。取得APIで版や文書種別を指定する方法も不明。
   - 引用: SCR-005 操作ボタン: コピーボタン、ダウンロードボタン、再生成ボタン、版切り替えボタン / GET /api/v1/projects/{id}/documents | 生成文書および版一覧取得
   - 理由: 自己診断結果(FR-006)の取得方法や、特定の文書・版を指定する識別方法がない。FR-008の直近3件の保持もAPIの応答で確認できない。
   - 改善案: 文書種別・版を指定するGETと、自己診断結果の返却項目、ダウンロード方法を追記する。
6. **[中程度 / 不整合]** FR-011, SCR-005, FR-008
   - 問題: 「版の履歴の画面」はShouldの将来拡張だが、SCR-005は版の履歴の表示と版切り替えボタンをMust画面に含めている。
   - 引用: FR-011: テンプレートの選択、版の履歴の画面、設計図(UML)の追加 / SCR-005: 版の履歴（直近3件）…版切り替えボタン
   - 理由: 版管理(FR-008)の範囲と将来拡張(FR-011)の境界が曖昧で、MVPで版の履歴画面を作るか不明。
   - 改善案: MVPでは版の閲覧・切り替えをSCR-005に含めるか決め、外部設計の記載を要件に合わせる。
7. **[中程度 / 設計]** POST /api/v1/projects/{id}/documents/upload, FR-003
   - 問題: 参考資料のサイズ上限・PDFのテキスト化失敗(画像のみPDFなど)・文字コードの扱い、およびテキスト化後の利用方法が記載されていない。
   - 引用: POST /api/v1/projects/{id}/documents/upload | 400 不正なファイル形式 / 2.5 バリデーション: ファイル形式は指定の拡張子のみ許可する
   - 理由: サイズ超過(413)やテキスト化失敗のエラー応答がなく、保持した資料をヒアリングや生成にどう使うかも不明。
   - 改善案: サイズ上限、テキスト化失敗時のエラーと画面表示、AIへの渡し方を追記する。
8. **[中程度 / 設計]** GET /api/v1/projects, POST /api/v1/projects, POST /api/v1/projects/{id}/chat, POST /api/v1/projects/{id}/documents/upload, POST /api/v1/projects/{id}/summary/approve, GET /api/v1/projects/{id}/documents
   - 問題: 認証が必要なAPIの認証方式(Authorizationヘッダ等)が明記されておらず、401・403・404の応答が各APIでそろっていない。ログアウト・トークン失効のAPIもない。
   - 引用: POST /api/v1/projects | 201 Created | 400 バリデーションエラー / CON-003: レート制限・トークン失効用にRedisを使用する
   - 理由: トークン失効を使うとあるのにログアウトAPIがなく、projects作成やchatには401・403・404が書かれていない。
   - 改善案: 全APIの共通の認証・認可エラーを定め、ログアウト(トークン失効)APIを追加する。
9. **[軽微 / 設計]** POST /api/v1/projects/{id}/chat, FR-002, NFR-003
   - 問題: チャットの応答は「最初の文字を数秒で出す」とあるが、APIは通常の200 OK(AI応答)で、ストリーミング方式が書かれていない。
   - 引用: NFR-003: チャットの最初の文字を数秒で出力 / POST /api/v1/projects/{id}/chat | 200 OK (AI応答)
   - 理由: NFR-003を満たすにはSSEなどの逐次返却が必要だが、外部設計に応答形式がない。
   - 改善案: 応答をストリーミングにするならその方式と、途中失敗時の扱いを追記する。
