## 設計レビュー
指摘 11件(最重要 1・中程度 8・軽微 2)

1. **[最重要 / ヒアリング・観点 security]** FR-001, SCR-002, GET /api/v1/projects, POST /api/v1/projects/{id}/chat, POST /api/v1/projects/{id}/summary/approve, GET /api/v1/projects/{id}/documents
   - 問題: セキュリティが「ログインをMVPに入れる」だけで、誰が誰のプロジェクト・文書・資料を見られるか(本人以外の閲覧・変更の可否)が決まっていない。公開サービスなのにアクセス制御の要件が無い。
   - 引用: security | AI の提案を採用 | ログインをMVPに入れる / FR-001 ユーザー登録およびログイン機能を提供する
   - 理由: 要件定義書 1.4 FR-001 にログインしか無く、{id} 付き API でプロジェクトの所有者だけが操作できるかが決められない。他人の文書の漏えいにつながる。
   - 改善案: プロジェクト・資料・文書は作成者本人のみ閲覧・操作可とする旨を利用者に確認し、要件と各 API の認可(403/404)に反映する。
2. **[中程度 / ヒアリング・観点 abuse]** NFR-008
   - 問題: 不正利用の対策が「回数上限を設ける」だけで、ログイン失敗・登録・チャット・生成それぞれの上限値・単位・超過時の扱いが決まっていない。
   - 引用: NFR-008 ログインの総当たり、登録の大量作成、チャットや生成の回数上限を設けて不正利用を防ぐ
   - 理由: 上限値が無いとレート制限(Redis)を実装できず、無料枠のLLM(CON-004)を使い切る恐れもある。
   - 改善案: 各操作の上限値(回数/時間・単位が IP かユーザーか)と超過時の応答を利用者に確認し、NFR-008 に書く。
3. **[中程度 / ヒアリング・観点 security]** FR-001, NFR-007
   - 問題: 認証トークンの扱い(有効期限・失効・保管場所)やパスワードの保存・強度規則が要件に無い。CON-003 でトークン失効に Redis を使うとあるが、仕様が未定。
   - 引用: POST /api/v1/auth/login | 200 OK (トークン返却) / CON-003 レート制限・トークン失効用にRedisを使用する
   - 理由: ログアウトや失効の API・画面が無く、トークンの寿命も決まっていないため、認証の設計が確定できない。
   - 改善案: トークンの種類・有効期限・ログアウト時の失効、パスワードの最低条件を利用者に確認して要件に加える。
4. **[中程度 / 設計]** POST /api/v1/projects/{id}/summary/approve, FR-005, FR-006, FR-009, NFR-003
   - 問題: 4文書の逐次生成と自己診断は数分かかるのに、承認 API が同期的な「200 OK (生成開始)」で、進捗の取得・完了通知・失敗時の再生成の API が無い。
   - 引用: POST /api/v1/projects/{id}/summary/approve | 構造化サマリ承認と文書生成開始 | 200 OK (生成開始) | 500 生成失敗 / SCR-005 操作ボタン: 再生成ボタン
   - 理由: 外部設計書 2.6 に生成状況の確認や再生成の API が無く、FR-009 の「生成失敗時は再生成できる」とSCR-005の再生成ボタンを満たす API が無い。
   - 改善案: 生成を非同期ジョブにして状況取得 API と文書単位の再生成 API を追加し、失敗時の状態を定義する。
5. **[中程度 / 設計]** SCR-004, SCR-003, POST /api/v1/projects/{id}/chat, FR-004
   - 問題: 画面にある「ヒアリング完了」「修正依頼」の操作に対応する API が無く、構造化サマリを作成・取得する API も無い。
   - 引用: SCR-003 操作ボタン: ヒアリング完了ボタン / SCR-004 操作ボタン: 承認して文書生成へ進むボタン、修正依頼ボタン / API一覧に summary の取得 API は無い
   - 理由: 外部設計書 2.6 の API は承認(approve)だけで、SCR-004 が表示するサマリの取得、ヒアリング完了、修正依頼の API が存在せず画面が動かない。
   - 改善案: ヒアリング完了・サマリ取得・修正依頼の API を追加し、画面との対応表に反映する。
6. **[中程度 / 設計]** SCR-005, FR-006, FR-007, FR-008, GET /api/v1/projects/{id}/documents
   - 問題: 版切り替え・再生成・ダウンロードに対応する API が無い。自己診断結果の取得も GET /documents に含まれるか不明で、FR-006 の API は承認 API に割り当てられている。
   - 引用: SCR-005 操作ボタン: コピーボタン、ダウンロードボタン、再生成ボタン、版切り替えボタン / FR-006 | SCR-005 | POST /api/v1/projects/{id}/summary/approve
   - 理由: 外部設計書 2.6 の API は GET /documents のみで、版の指定取得・再生成・診断結果の取得の方法が不明。2.3 のSCR-005 のアクションも「各種操作に応じた機能を実行する」としか書かれていない。
   - 改善案: 版指定の文書取得、再生成、診断結果の取得の API を追加し、FR-006 の対応 API を見直す。
7. **[中程度 / 設計]** POST /api/v1/projects/{id}/chat, POST /api/v1/projects/{id}/documents/upload, NFR-003
   - 問題: チャットは最初の文字を数秒で出すストリーミング要件だが、API は「200 OK (AI応答)」の一括応答としか書かれていない。また、チャット履歴の取得 API が無い。
   - 引用: NFR-003 チャットの最初の文字を数秒で出力し / POST /api/v1/projects/{id}/chat | 200 OK (AI応答)
   - 理由: 外部設計書 2.6 で応答方式が決まっておらず、NFR-003 を満たせるか分からない。履歴を再表示する SCR-003 の「チャット履歴」の取得手段も無い。
   - 改善案: チャットを SSE 等のストリーミングと明記し、履歴取得 API を追加する。
8. **[中程度 / 設計]** POST /api/v1/projects/{id}/documents/upload, FR-003
   - 問題: 参考資料のファイルサイズ上限・PDF のテキスト抽出失敗時(画像のみ等)の扱い・413 や 422 などのエラーが定義されていない。
   - 引用: バリデーション: ... ファイル形式は指定の拡張子のみ許可する。 / エラー: 400 不正なファイル形式
   - 理由: 外部設計書 2.5 にサイズ制限が無く、大きいファイルや抽出失敗時の動作が決まっておらず、FR-009 の例外処理とも整合しない。
   - 改善案: サイズ上限と抽出失敗時のエラー応答を加え、保持した資料の扱いを定義する。
9. **[中程度 / 不整合]** FR-009, POST /api/v1/projects/{id}/chat, CON-004
   - 問題: LLM の無料枠の上限超過・レート制限の応答が API のエラーに無い(AI応答失敗が 500 のみ)。回数上限(NFR-008)を超えたときの 429 や、未認証・認可の 401/403 も多くの API で無い。
   - 引用: POST /api/v1/projects/{id}/chat | エラー: 400 文字数超過・空送信エラー, 500 AI応答失敗 / POST /api/v1/projects | 400 バリデーションエラー
   - 理由: 要件定義書 CON-004 と NFR-008 は上限超過時のエラー処理を求めるが、外部設計書 2.6 に 429 が無く、chat・upload・approve・projects 作成に 401 も無い。
   - 改善案: 全 API に 401・403、上限が関わる API に 429、LLM 上限超過用の理由付きエラーを追加する。
10. **[軽微 / 不整合]** FR-005, SCR-002, FR-002, POST /api/v1/projects
   - 問題: SCR-002 が FR-005 に紐づいているが、文書生成は SCR-004/005 の操作で、SCR-002 に生成の機能が無い。
   - 引用: SCR-002 | プロジェクト一覧・作成画面 | ... | FR-002・FR-005 / FR-005 | SCR-002・SCR-005
   - 理由: 外部設計書 2.2 と付録の対応が 2.3 の画面仕様と合っていない。
   - 改善案: SCR-002 から FR-005 の対応を外すか、SCR-002 での生成・文書への導線を書く。
11. **[軽微 / 設計]** NFR-002, CON-005, NFR-007
   - 問題: バックアップ(毎日・7日分・VPS外コピー)と操作記録の保存の実現方法が外部設計書の構成に出てこない。
   - 引用: NFR-002 データベースを毎日バックアップし7日分を残しVPS外へもコピーする / 2.1 の構成図にバックアップ先が無い
   - 理由: 外部設計書 2.1 の構成に無く、実装計画で漏れやすい。
   - 改善案: 構成図にバックアップ先を足し、実装計画にバックアップと操作ログのタスクを入れる。
