実装前提・制約

技術スタック・開発環境(実装計画書 4.3・内部設計書 3.1)

開発言語はPython 3.13およびNext.js(App Router)を用い、データベースにはPostgreSQLおよびRedisを採用する。サーバー環境としてDocker ComposeとnginxをVPS上に構築し、GitHub Actionsを用いて自動デプロイを実施する。テスト・自動化およびコード品質維持のため、適切なユニットテスト・統合テストを継続的に行う方針とする。 技術スタック: - フロントエンド: Next.js (App Router), Tamagui - バックエンド: FastAPI, Python 3.13, LangChain, LangGraph - データベース: PostgreSQL (リレーショナルデータ保存), Redis (レート制限およびトークン失効管理) - インフラ: VPS, Docker Compose, nginx, GitHub Actions (自動デプロイ) アーキテクチャ方針: フロントエンドはSSR/CSRを適切に組み合わせたNext.js App Router構成を採用し、Tamaguiによりクロスプラットフォーム対応のUIを構築する。バックエンドはFastAPIによる非同期REST APIサーバーを構築し、LangChainおよびLangGraphを用いてGemini Flash-Liteとの対話フローや設計書生成ワークフローを制御する。セキュリティ・不正利用対策としてRedisを用いたレート制限ミドルウェアを導入し、全APIへのアクセス制御を行う。

実装ルール(内部設計書 3.3・3.4より)

  • モジュールは、内部設計書のモジュール一覧の依存先にだけ依存する(層を飛び越さない)。
  • 3.4 共通エラーレスポンス形式として、HTTPステータスコードに応じたJSONオブジェクト（error, message, details）を返却する。
  • 3.4 認証失敗は 401、権限・所有者違反は 403、リソース不存在は 404、入力不備は 400、レート制限超過は 429、AI応答失敗や生成失敗は 500 を返す。
  • 3.4 Redisを利用したレート制限ミドルウェアにより、不正な大量アクセスや無料枠の保護を行う。
  • 3.4 セキュリティ要件（NFR-007）に基づき、ログにはプロンプトやチャットの本文を残さず、メタデータとエラーコードのみを記録する。

目的

4種設計書および自己診断の一括生成、保存済み設計書の履歴一覧取得、個別詳細取得のAPIエンドポイントと関連するサービス・リポジトリ処理を実装する。

対象の処理・参照する設計

  • 内部設計書 DF-3 POST /api/v1/documents/generate
  • 内部設計書 DF-4 GET /api/v1/documents
  • 内部設計書 DF-9 GET /api/v1/documents/{id}
  • 内部設計書 3.3 backend/app/api/v1/documents.py
  • 内部設計書 3.3 backend/app/services/ai_service.py
  • 内部設計書 3.3 backend/app/repositories/document_repo.py

作成・変更するファイル(依存順)

ファイル種類責務根拠
backend/app/repositories/document_repo.pyモジュールPostgreSQLのdocumentsテーブルに対するCRUD操作のカプセル化を行う内部設計書 3.3
backend/app/services/ai_service.pyモジュールLangChainとLangGraphを用いたGemini Flash-Liteによる4種設計書と自己診断結果の生成処理を行う内部設計書 3.3
backend/app/api/v1/documents.pyモジュール設計書の生成、履歴一覧取得、個別詳細取得のリクエスト受付、認証および所有者検証を行う内部設計書 3.3
backend/tests/api/v1/test_documents.pyテスト設計書の生成、履歴一覧取得、個別詳細取得APIの動作を検証する実装計画書 4.3

実装の要点(設計に書いていないことだけ)

  • リポジトリ層を作成した後にサービス層を実装し、最後にAPIルーター層を実装する順序とする
  • 既存の認証部品やRedisレート制限ミドルウェアを再利用する

テスト観点

#観点SUTドライバスタブ
TC-01正常なチャットセッションIDを指定して設計書一括生成が成功することPOST /api/v1/documents/generate結合テスト(FastAPI TestClient)ai_service.pyのGemini Flash-Lite呼び出しをモック化する
TC-02認証トークンを使用して保存済み設計書の履歴一覧が取得できることGET /api/v1/documents結合テスト(FastAPI TestClient)スタブ不要 ── テスト用DBのデータを参照する
TC-03存在する文書IDを指定して個別詳細が取得できることGET /api/v1/documents/{id}結合テスト(FastAPI TestClient)スタブ不要 ── テスト用DBのデータを参照する
  • Given: 有効なチャットセッションと認証トークンが存在する
  • When: POST /api/v1/documents/generateを呼び出す
  • Then: 4種設計書と自己診断結果が生成されデータベースに保存される

確認方法

  • pytestを実行し、documents関連のテストがすべて成功することを確認する
