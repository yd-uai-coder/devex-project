## 2. 実装前提・制約

### 技術スタック・開発環境(実装計画書 4.3・内部設計書 3.1)

開発言語はPython 3.13およびNext.js(App Router)を用い、データベースにはPostgreSQLおよびRedisを採用する。サーバー環境としてDocker ComposeとnginxをVPS上に構築し、GitHub Actionsを用いて自動デプロイを実施する。テスト・自動化およびコード品質維持のため、適切なユニットテスト・統合テストを継続的に行う方針とする。

技術スタック:
- フロントエンド: Next.js (App Router), Tamagui
- バックエンド: FastAPI, Python 3.13, LangChain, LangGraph
- データベース: PostgreSQL (リレーショナルデータ保存), Redis (レート制限およびトークン失効管理)
- インフラ: VPS, Docker Compose, nginx, GitHub Actions (自動デプロイ)

アーキテクチャ方針:
フロントエンドはSSR/CSRを適切に組み合わせたNext.js App Router構成を採用し、Tamaguiによりクロスプラットフォーム対応のUIを構築する。バックエンドはFastAPIによる非同期REST APIサーバーを構築し、LangChainおよびLangGraphを用いてGemini Flash-Liteとの対話フローや設計書生成ワークフローを制御する。セキュリティ・不正利用対策としてRedisを用いたレート制限ミドルウェアを導入し、全APIへのアクセス制御を行う。

### 実装ルール(内部設計書 3.3・3.4より)

- モジュールは、内部設計書のモジュール一覧の依存先にだけ依存する(層を飛び越さない)。
- 3.4 共通エラーレスポンス形式として、HTTPステータスコードに応じたJSONオブジェクト（error, message, details）を返却する。
- 3.4 認証失敗は 401、権限・所有者違反は 403、リソース不存在は 404、入力不備は 400、レート制限超過は 429、AI応答失敗や生成失敗は 500 を返す。
- 3.4 Redisを利用したレート制限ミドルウェアにより、不正な大量アクセスや無料枠の保護を行う。
- 3.4 セキュリティ要件（NFR-007）に基づき、ログにはプロンプトやチャットの本文を残さず、メタデータとエラーコードのみを記録する。
