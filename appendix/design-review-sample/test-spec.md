# テスト仕様書の見本(Phase 51)

ステージ8で Devex が生成する「テスト仕様書」の形の見本。題材は Devex 自身の詳細設計モードの生成物(`stage7-effect/hearing/detailed-3`。要件定義書・外部設計書・詳細設計書・実装計画書)。規則は [README](./README.md) と [Phase 51-2](../../textbook/Phase-51/Phase-51-2.md) の決定7・8。

- **対象**: 結合テスト(API 単位で、ルーターから DB まで通す)と総合テスト(画面の操作の流れ・非機能要件)。日本の実務の「結合テスト仕様書」「総合テスト仕様書」に当たる。
- **単体テスト**: 今の実装手順書のテスト観点(SUT / ドライバ / スタブ)のまま。この文書には書かない。
- **作り方**: 生成のモデル(Gemini)が model(構造化出力)を作り、md はコードが組み立てる(要件定義書と同じ「構造化出力 → model → md」)。レビューには渡さない。決定的な検証で、Must の要件にテストが無い・存在しない要件 ID や API を指す・異常系のテストが1件も無い API を指摘する(この見本では FR-007 のコピーのテストが無い、が当たる)。
- **生成のとき**: 簡易 = 4文書の後、詳細 = 段階7の承認の後。

以下は、生成物の形を示すために人が書いた見本(実物の設計の穴 ── 例えば持ち主の確認が無い ── は、テストの「期待結果」として書き、設計に無いことは「設計に無い」と印を付ける)。

# テスト仕様書: Devex

## 1 テストの方針

| 項目 | 内容 |
|---|---|
| 対象 | 外部設計書 2.6 の API 8本、画面 SCR-001〜SCR-005 の操作の流れ、非機能要件 NFR-001〜NFR-009 |
| 範囲外 | Should 以下の要件(FR-011)、MVP の後と決めたもの(NFR-004 の監視・追跡、NFR-005 の削除) |
| 観点 | 正常・異常・境界・セキュリティ・非機能 |
| 環境 | Docker Compose(PostgreSQL・Redis)。LLM は偽 LLM(決まった応答・失敗を返す)に差し替える。非機能のうち性能は本物の LLM で測る |
| 完了条件 | Must の要件すべてにテストがあり、最重要の観点(認証・認可・データの保全)のテストがすべて成功する |

## 3 総合テスト(画面の流れ・非機能)

| テストID | 対象 | 観点 | 手順 | 期待結果 | 要件 |
|---|---|---|---|---|---|
| ST-001 | SCR-001 → SCR-005 | 正常 | 登録 → ログイン → プロジェクト作成 → 資料のアップロード → チャット → ヒアリング完了 → サマリ承認 → 文書の確認・ダウンロード | 途中で止まらずに4文書をダウンロードできる | FR-001〜FR-008 |
| ST-002 | SCR-003 | 非機能 | 十数人が同時にチャットする | 最初の文字が数秒で出る | NFR-003 |
| ST-003 | SCR-004 → SCR-005 | 非機能 | 承認して生成を待つ | 数分以内に4文書がそろう | NFR-003 |
| ST-004 | 運用 | 非機能 | バックアップの処理を流し、別の環境に戻す | 7日分が残り、VPS の外のコピーから戻せる | NFR-002 |
| ST-005 | ログ | セキュリティ | チャットを送ったあとのログを見る | 入力内容がログに無く、操作の記録だけがある | NFR-007 |
| ST-006 | 対応ブラウザ | 非機能 | Chrome・Edge・Firefox・Safari の最新版、スマートフォンで開く | PC は操作でき、スマートフォンは閲覧できる | NFR-009 |
