# M-01-T01 開発環境と横断事項の土台

> 見本([README](../README.md))。処理を持たない「基盤」の単位。参照先は段階7の開発環境と07章の横断事項になる。
> 種別: 基盤 / マイルストーン: M-01 環境構築と認証・横断事項の実装 / 依存: なし

## 目的

Docker Compose で開発環境が起動し、どの機能の単位からも使う横断事項(例外の HTTP への変換・ログ・Redis への接続)がそろった状態にする。

## 対象の処理・参照する設計

- 処理: なし(基盤)
- 開発環境: 段階7 開発環境
- モジュール: 段階4 `cache/redis_client.py`
- 横断事項: 07章 例外と HTTP・ログ・レート制限

## 作成・変更するファイル(依存順)

| ファイル | 責務 | 根拠 |
|---|---|---|
| `docker-compose.yml` | backend・frontend・PostgreSQL・Redis の起動 | 段階7 環境・設定のファイル(例) |
| `Dockerfile` | backend のイメージ | 同上 |
| `frontend/package.json` | frontend の依存 | 同上 |
| `cache/redis_client.py` | Redis への接続(レート制限と、トークンの失効で使う) | 段階4 |
| `main.py` | アプリの組み立てと、例外から HTTP への共通の変換 | 07章 例外と HTTP(段階4に無い ── 未定義を参照) |
| `tests/unit/test_errors.py` | 例外の種類ごとに、07章のステータスになることのテスト | 手順書で決める |

## 実装の要点(設計に書いていないことだけ)

- 環境のファイルを先に作り、compose で起動できることを確かめてから、横断事項に進む。
- この単位では機能を作らない。例外の変換は、テスト用のダミーの例外で確かめる。

## テスト観点

| # | 観点 | SUT | ドライバ | スタブ |
|---|---|---|---|---|
| TC-01 | 例外の種類ごとに、07章のステータスになる(入力 400 / 認証 401 / 無い 404 / 想定外 500) | 例外から HTTP への変換 | 結合テスト(テスト用のルートを足したアプリを httpx の AsyncClient で呼ぶ) | スタブ不要 ── 変換は外部依存を呼ばないため |

## 確認方法

- `docker compose up` で全コンテナが起動する。
- 上のテストが通る。

## 未定義・要決定

| 重要度 | 出どころ | 対象 | 内容 |
|---|---|---|---|
| 最重要 | AI | 07章 例外と HTTP | 変換する場所が「各エンドポイント」とあるだけで、共通のハンドラにするかが決まっていない(この手順書は共通のハンドラを前提にしている) |
| 中程度 | 検証 | 段階4 | `main.py` が段階4のモジュール一覧に無い(`UNKNOWN_MODULE`)。共通の例外ハンドラを置く場所として、段階4に足すかを決める |
| 中程度 | AI | 07章 レート制限 | 上限の値(何秒に何回)が無い |
