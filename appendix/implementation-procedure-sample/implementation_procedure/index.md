# 実装手順書: Devex

> 見本([README](../README.md))。この index は、本実装では決定論的に組み立てる(LLM を使わない)。
> 元にした設計: 段階1〜7(承認済み)。段階7は[改修後の形](../stage7-recut.md)。

## 1. 実装概要

### 対象

段階7のマイルストーン M-01〜M-04(すべて Must)。処理 F-01〜F-11。

| マイルストーン | ゴール |
|---|---|
| M-01 環境構築と認証・横断事項の実装 | 開発環境が構築され、JWT認証およびエラーハンドリング・Redis連携を含む横断事項が機能するようになる。 |
| M-02 プロジェクト管理と参考資料アップロード機能の実装 | プロジェクトの作成および参考資料(txt/md/pdf)のアップロード・テキスト抽出ができるようになる。 |
| M-03 AI対話ヒアリングとSSEストリーミングの実装 | LangGraph制御による対話型ヒアリングとSSEストリーミングによるリアルタイム応答が可能になる。 |
| M-04 4種設計書の自動生成と自己診断・閲覧機能の実装 | ヒアリング結果の承認から非同期による4種の設計書生成、および自己診断とバージョン管理付き閲覧・プレビューができるようになる。 |

### 対象外

要件定義書 1.4 の Should / Could / Won't(手順書を作らない)。

- Should: 過去のチャット履歴・生成文書の閲覧・比較・復元画面、テンプレート選択機能
- Could: 生成文書のエクスポート形式追加(PDF、Word など)
- Won't: 外部サービス連携、音声入力、同時編集機能

## 2. 実装前提・制約

### 技術スタック(段階7 開発環境)

Python 3.13、FastAPI、Next.js (App Router) + Tamagui、PostgreSQL、Redis、Docker Compose、GitHub Actions、pytest。

### 実装ルール(段階4・07章より)

- 層は 入口 → ユースケース → 永続化 / 外部連携 の向きにだけ依存する(段階4: 層と依存先)。
- ルート(`api/routes/*`)は、リポジトリ・外部連携を直接呼ばない(段階4: 依存先)。
- 例外は各エンドポイントで一括して HTTP に変換する。入力 400 / 認証 401 / 無い 404 / 想定外 500(07章: 例外と HTTP)。
- 書き込みはリポジトリでトランザクションを管理し、サービスの処理が成功したら commit、例外なら rollback(07章: トランザクション)。
- パスワード・トークンをログに出さない(07章: ログ)。
- 外部サービスの呼び出しは、タイムアウトとレート制限を考えて例外処理とリトライを行う(07章: 外部サービスの呼び出し)。
