# 2. 外部設計書

## 2.1 システム構成概要
- システムの全体像と外部との関係性（テキストによる構造記述）

```text
[ ユーザー (Webブラウザ) ]
         │
         │ HTTPS (REST API / JSON / JWT認証)
         ▼
[ Webアプリケーション / APIサーバー ]
         │
         ├─► [ PostgreSQL (データ永続化) ]
         │      - ユーザー情報
         │      - チャット履歴
         │      - 生成文書 (版管理: 直近3件)
         │
         └─► [ 外部LLM API (Gemini Flash-Lite) ]
                - ヒアリング対話生成
                - 構造化サマリ作成
                - 4種設計書一括生成
                - AI自己診断 (不足点分析)
```

## 2.2 画面一覧・画面遷移フロー（概要）

### 画面一覧
| 画面ID | 画面名 | 主要な役割 | 優先度 |
|:---:|:---:|:---|:---:|
| SCR-001 | ログイン・新規登録画面 | ユーザー認証（メール/パスワード）およびアカウント作成を行う | Must |
| SCR-002 | ホーム・ダッシュボード画面 | 新規プロジェクトの開始、過去のプロジェクト・設計書一覧の確認を行う | Must |
| SCR-003 | 参考資料アップロード画面 | 設計書のベースとなる参考資料（最大3件、txt/md/pdf）をアップロードする | Must |
| SCR-004 | 対話型ヒアリングチャット画面 | AI主導のヒアリング、対話、構造化サマリの確認と承認を行う | Must |
| SCR-005 | 設計書生成・プレビュー画面 | 4種のMarkdown設計書の一括生成、プレビュー、自己診断、ダウンロードを行う | Must |

### 画面遷移フロー
```text
[SCR-001 ログイン/新規登録]
         │ (認証成功)
         ▼
[SCR-002 ホーム・ダッシュボード]
         │ (新規プロジェクト開始)
         ▼
[SCR-003 参考資料アップロード] (最大3件 / スキップ可)
         │
         ▼
[SCR-004 対話型ヒアリングチャット]
         │ (AI質問 ⇄ ユーザー回答)
         │ (構造化サマリ提示 ＆ ユーザー承認)
         ▼
[SCR-005 設計書生成・プレビュー]
         ├─► 要件定義 / 外部設計 / 内部設計 / 実装計画の切替・プレビュー
         ├─► AI自己診断結果確認 (3段階)
         ├─► クリップボードへコピー / ファイルダウンロード
         └─► [SCR-004 チャット画面へ戻る] ➔ 追加回答 ➔ 再生成
```

## 2.3 主要画面のUI/UX仕様

### SCR-001: ログイン・新規登録画面
- **入力項目**:
  - メールアドレス（テキスト入力、バリデーション: メール形式）
  - パスワード（パスワード入力、バリデーション: 8文字以上）
- **表示項目**:
  - タブ切り替え（「ログイン」/「新規登録」）
  - エラーメッセージ表示エリア
- **操作ボタン**:
  - 「ログイン」/「アカウント作成」ボタン（主要アクション）
- **アクション**:
  - 認証成功時、アクセストークンを保持し、SCR-002（ホーム画面）へ遷移する。リフレッシュトークンはHttpOnly Cookieに格納される。

### SCR-002: ホーム・ダッシュボード画面
- **表示項目**:
  - ログインユーザーのメールアドレス、ログアウトボタン
  - 既存プロジェクト一覧（プロジェクト名、更新日時、ステータス）
- **操作ボタン**:
  - 「新規プロジェクト作成」ボタン
  - プロジェクトカードクリック（該当プロジェクトの最新状態へ遷移）
- **アクション**:
  - 「新規プロジェクト作成」押下時、SCR-003（参考資料アップロード画面）へ遷移する。

### SCR-003: 参考資料アップロード画面
- **入力項目**:
  - 参考資料ファイル選択（ドラッグ＆ドロップ対応、最大3件まで、許可形式: `.txt`, `.md`, `.pdf`）
- **表示項目**:
  - 選択中ファイル一覧（ファイル名、サイズ、削除ボタン）
  - アップロード制限の注意書き（最大3件、対応形式）
- **操作ボタン**:
  - 「ファイルをアップロードしてチャットを開始する」ボタン
  - 「資料なしで進める」スキップボタン
- **アクション**:
  - ファイルをアップロード（またはスキップ）し、SCR-004（対話型ヒアリングチャット画面）へ遷移する。

### SCR-004: 対話型ヒアリングチャット画面
- **表示項目**:
  - チャット履歴エリア（AIの質問とユーザーの回答が時系列で表示）
  - 構造化サマリモーダル / 承認パネル（AIによるヒアリング内容のサマリ提示時）
- **入力項目**:
  - チャット入力欄（テキストエリア、複数行対応）
- **操作ボタン**:
  - 「送信」ボタン
  - 「サマリを承認して設計書を生成する」ボタン（サマリ提示後に活性化）
- **アクション**:
  - メッセージ送信後、LLM（Gemini Flash-Lite）からの応答（3秒以内を目指す）を非同期で取得・表示する。
  - 要件が十分に網羅されたとAIが判断して構造化サマリを提示し、ユーザーが「承認」ボタンを押下すると、SCR-005（設計書生成・プレビュー画面）へ遷移する。

### SCR-005: 設計書生成・プレビュー画面
- **表示項目**:
  - 設計書タブ（「要件定義」「外部設計」「内部設計」「実装計画」の切り替え）
  - マークダウンプレビューエリア
  - AI自己診断パネル（最重要・中程度・軽微の3段階で不足点を表示）
  - 版管理情報（直近3件の履歴選択ドロップダウン）
- **操作ボタン**:
  - 「クリップボードにコピー」ボタン
  - 「ファイルダウンロード（.md）」ボタン
  - 「チャットに戻って修正・追加する」ボタン
  - 「設計書を再生成する」ボタン
- **アクション**:
  - 非同期で4種の設計書を一括生成中、ローディングスピナーおよびプログレス表示を行う。
  - LLM上限超過エラー時は、再送促しメッセージと「再試行」ボタンを表示する。

## 2.4 外部システム・API連携仕様
- **連携サービス / API**:
  - Google Gemini API (Gemini Flash-Liteモデル)
- **認証方式**:
  - APIキー認証（サーバーサイドの環境変数にて安全に管理）
- **データ連携タイミング**:
  - ユーザーとのチャットメッセージ送信時（リアルタイム対話）
  - 構造化サマリの生成時
  - 4種設計書の一括生成時（非同期処理）
  - AI自己診断の実行時
- **エラーハンドリング**:
  - レートリミット（429 Too Many Requests）やAPIエラー発生時は、システム側で指数バックオフによる自動リトライ、またはユーザーへの再送促しメッセージ（再試行ボタン）を表示する。

---

## 2.5 データ入出力仕様

### ファイル入出力仕様
- **参考資料アップロード**:
  - **受付フォーマット**: `.txt`, `.md`, `.pdf`
  - **ファイル数制限**: 最大3件
  - **容量制限**: 1ファイルあたり最大 10MB
  - **バリデーションルール**:
    - 拡張子が指定のもの以外はエラーとする。
    - 3件を超えるアップロード要求は拒否する。
    - サーバ側でMimeTypeおよびファイルの実体ヘッダを検証する。
- **設計書ダウンロード**:
  - **出力フォーマット**: Markdown形式 (`.md`)
  - **文字コード**: UTF-8 (BOMなし)
