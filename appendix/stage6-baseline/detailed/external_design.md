# 2. 外部設計書

## 2.1 システム構成概要
本システムは、ユーザーからのブラウザ経由のリクエストを受け付けるWebアプリケーションサーバーと、非同期処理を実行するジョブワーカー、データを永続化するPostgreSQL、および外部のLLMプロバイダー（AI）によって構成されます。

```text
[ ユーザー (Web Browser) ]
       │
       ▼ (HTTPS)
[ Web Application / API Server ]
  ├── 認証管理モジュール (JWT Session)
  ├── チャット・ヒアリング制御モジュール
  ├── 非同期ジョブ・キューイングマネージャー (Redis / BullMQ 等)
  └── ドキュメント・版管理モジュール
       │                         │                     │
       ▼ (REST API)              ▼ (SQL)               ▼ (Queue)
[ LLM Provider (AI) ]     [ PostgreSQL (DB) ]   [ Background Worker ]
```

- **Web Application / API Server**: フロントエンドへのUI提供およびAPIルーティング、チャット・設計書生成・自己診断のビジネスロジックを処理。
- **Background Worker**: ユーザー承認後に発生する「要件定義 → 外部設計 → 内部設計 → 実装計画」の連続生成処理を非同期で実行。
- **PostgreSQL**: ユーザー情報、チャット履歴、参考資料、生成文書（版管理：直近3件）を安全に永続化。
- **LLM Provider**: ヒアリング対話、構造化サマリ作成、設計書一括生成、自己診断を担う外部AIエンジン。

## 2.3 主要画面のUI/UX仕様

### 2.3.1 SCR-003: 資料アップロード・初期アイデア入力画面
- **入力項目**:
  - 参考資料ファイル（ドラッグ＆ドロップ対応、`txt` / `md` / `pdf`、最大3件まで）
  - 初期アイデア・要望テキスト（テキストエリア、Markdown対応）
- **表示項目**:
  - アップロード済みファイル一覧（ファイル名、サイズ、削除ボタン）
  - 入力文字数カウンター
- **操作ボタン**:
  - 「ファイルをアップロード」ボタン
  - 「AIヒアリングを開始する」ボタン（バリデーション通過後に活性化）
- **アクション**:
  - 「AIヒアリングを開始する」押下時、ファイルとテキストをサーバーへ送信し、SCR-004（ヒアリング画面）へ遷移。

### 2.3.2 SCR-004: AIヒアリング・チャット画面
- **入力項目**:
  - チャットメッセージ入力欄（テキストエリア）
- **表示項目**:
  - チャット履歴タイムライン（ユーザー発言 / AIの質問・応答）
  - 現在のヒアリング進捗ステータス（例：「要件定義の深掘り中: 3/5」）
  - 構造化サマリモーダル／パネル（AIが十分な情報を取得したと判断した際に出現）
- **操作ボタン**:
  - 「送信」ボタン
  - 「構造化サマリを確認する」ボタン
  - 「サマリを承認して設計書生成へ進む」ボタン（サマリモーダル内）
- **アクション**:
  - メッセージ送信後、数秒以内でAIの返答がストリーミングまたはローディング後に表示される。
  - サマリ承認アクションにより、非同期ジョブがキックされ、SCR-005（進捗画面）へ遷移。

### 2.3.3 SCR-006: 設計書プレビュー・自己診断画面
- **入力項目**:
  - 追加修正指示用のチャット入力欄（各設計書タブ内、または共通ペイン）
- **表示項目**:
  - タブ切り替えメニュー（要件定義書 / 外部設計書 / 内部設計書 / 実装計画書）
  - マークダウンプレビュー領域
  - AI自己診断結果ウィジェット（3段階バッジ：最重要 / 中程度 / 軽微、および改善提案テキスト）
  - 版管理セレクター（直近3件の版切り替えプルダウン、版の日時表示）
- **操作ボタン**:
  - 「Markdownをコピー」ボタン
  - 「Markdownをダウンロード (.md)」ボタン
  - 「追加修正を反映して再生成」ボタン
- **アクション**:
  - コピーボタン押下でクリップボードにMarkdownを格納。
  - ダウンロードボタンで `.md` ファイル形式でローカル保存。
  - 追加修正指示を送信するとバックグラウンドで該当文書が再生成され、新版（直近3件の枠内）として版がインクリメントされる。

## 2.4 外部システム・API連携仕様

- **LLM Provider API (例: OpenAI API / Anthropic API等)**
  - **認証方式**: Bearer Token (環境変数による安全なサーバーサイド保持)
  - **データ連携タイミング**:
    1. ヒアリング時の対話生成（都度リクエスト）
    2. サマリ作成時の構造化抽出リクエスト
    3. 4種設計書の非同期一括生成リクエスト（依存関係を考慮した順次プロンプト送信）
    4. 自己診断スコアリングリクエスト

## 2.5 データ入出力仕様

### 2.5.1 参考資料ファイル入出力
- **対応フォーマット**: `.txt`, `.md`, `.pdf`
- **受付制限**: 1ファイルあたり最大 10MB、合計最大3件まで
- **バリデーションルール**:
  - 拡張子チェック (`.txt`, `.md`, `.pdf` 以外はエラー)
  - ファイルサイズチェック
  - MIMEタイプ検証

### 2.5.2 設計書ファイル出力
- **フォーマット**: Markdown形式 (`.md`)
- **文字コード**: UTF-8 (BOMなし)
- **ファイル命名規則**: `<project_name>_<document_type>_v<version>.md` (例: `ec-site_external-design_v1.md`)
