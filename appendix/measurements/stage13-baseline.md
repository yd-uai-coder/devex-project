# ステージ13 のベースライン(Phase 100-2)

ステージ13(説明とすり合わせ)の効果を後で比べるために、今の Devex(ステージ12 の版)が出す変更の説明書を、クライアント役が読んで、合意・却下を判断できるかを記録する。決定と経緯は [Phase 100-2](../../textbook/Phase-100/Phase-100-2.md)。

## 条件

- 題材: 開発環境のプロジェクト「トレンド追跡アプリ」(詳細設計モード)の CR-3・CR-4。どちらも反映済み(Phase 89・99 の実 LLM の一巡で作ったもの)。
  - CR-3: FR-001 の取得の間隔を 8時間 → 12時間。基準の束 B-3。変更後の案は空。要約は「確認済み」だが、CR が変わった後なので「古い」で、出力に載らない。
  - CR-4: FR-003 のランキングを TOP10 → TOP20 にし、前回からの順位の変動を矢印で示す。基準の束 B-4。変更後の案あり。要約なし。
- 説明書: 今の Devex がダウンロードで出す md(5節)。[`stage13/measure.py`](./stage13/measure.py) が開発環境の backend コンテナの中で本体のサービスを呼び、[`stage13/data/explanations.json`](./stage13/data/explanations.json) に書き出した(読むだけ。LLM なし。2回流して同じ出力)。
- クライアント役: Claude が [`stage13/client.md`](./stage13/client.md) の規則で読んだ(LLM の費用 0)。
- 実際の規模: [ステージ12 の効果測定](./stage12-effect.md) と開発 DB(段階1 の model・束の写し)から。

## 結果

### 判断

| CR | 判断 | 判断に要る問い(説明書の中で答えが無い) | 残った疑問(判断には関わらない) |
|---|---|---|---|
| CR-3 | 合意 | なし | 範囲(影響0件・作業0件で本当によいか)・前提(「推測の要件」「ヒアリングで決まっていない観点」が何を意味し、自分が何かを決める必要があるのか) |
| CR-4 | **判断できない** | 範囲(画面の表示を変えるのに作業0件・テスト0件)・費用・期間(どれくらいの手間か) | 選択肢(矢印のほかの見せ方)・結果(「前回」はいつの取得か)・前提(CR-3 と同じ) |

- CR-3 は、頼んだ本人が、合意済みの文と変更の内容(8時間 → 12時間)を見比べれば決められる。説明書の数字(影響0件)は、間隔の変更として明らかに合わないとは言えない(規則4)。
- CR-4 は、画面を変えるのに作業0件・テスト0件と書いてあり、規則4 の「明らかに合わない数字」に当たる。手間の目安も無く、決められない。

### 規模の表示と実際

| CR | 説明書の予測 | 説明書の作業単位・テスト | 実際 |
|---|---|---|---|
| CR-3 | 0件 | 0件・0件 | 予測 0 = 実際 0([Phase 89-4](../../textbook/Phase-89/Phase-89-4.md)) |
| CR-4 | 1件(SCR-001 トップページ) | 0件・0件 | 段階1 を CR-4 で2回作り直し、承認で結んだ印は **40件**(ステージ12 の効果測定) |

- **CR-4 の0件の原因**: 束 B-4 の段階1〜8 は、どれも「古い」の状態で写されていた。B-4 の段階1 の処理(4件)は、どれも要件 ID(`req_ids`)が空だった(古い生成の版)。予測は要件 → 処理 → その先とたどるので、FR-003 から処理に届かず、画面1件で止まった。今の段階1 は、処理ごとに要件 ID を持つ(F-30 = FR-003 など)。
- 説明書は、数えた結果の0件と、たどれなくて数えられなかった0件を区別しない。
- ファイルの数は、説明書に出ない(作業単位とテストだけ)。

### 説明書の言葉

規則5 で数えた、業務の語でなく、説明書の中で説明もされない語。

| CR | 技術の語 | ID | Devex の用語 |
|---|---|---|---|
| CR-3 | X API・定期バッチ処理 | B-3・FR-001 | 合意済みの版・推測の要件・観点 |
| CR-4 | Jinja2テンプレート | B-4・FR-003・SCR-001 | 合意済みの版・推測の要件・観点 |

- 技術の語は、どれも要件の文(合意の対象)の中にある。
- 4節の「推測の要件」は、対象の要件そのもの(CR-3 は FR-001、CR-4 は FR-003)で、「利用者に確かめていません」と書いてある。クライアント役には、自分が何を確かめればよいかが分からない。

### 選択肢

どちらの説明書にも無い(今の CR に案を複数持つ項目が無い)。
