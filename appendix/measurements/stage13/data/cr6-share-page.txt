1. 変更の内容と背景

この節は、何を・なぜ変えるかです。

CR-4 で画面のランキングを TOP20 にしたが、取得(FR-001)は TOP10、背景解説(FR-002)は上位10件のままで、11〜20位の取得と解説の扱いが決まっていない。表示・取得・解説の件数をそろえたい。

背景	内容
出どころ	打ち合わせ
日付	2026-10-25
メモ	定例の打ち合わせで、11〜20位を押しても解説が出ないと指摘された
2. 対象の要件

この節は、合意済みの要件のうち変わるものです。「合意済みの文」が今の合意、「変更後の案」がこの変更で合意したい文です。

要件 ID	変更の種類	合意済みの文	変更後の案
FR-001	内容の変更	12時間ごとにX APIから日本国内のトレンドランキングTOP10を取得する定期バッチ処理を実装する。	12時間ごとにX APIから日本国内のトレンドランキングTOP20を取得する定期バッチ処理を実装する。
FR-002	内容の変更	トレンド取得と同時にLLMを用いて上位10件分の背景解説を自動生成しデータベースに保存する。	トレンド取得と同時にLLMを用いて上位20件分の背景解説を自動生成しデータベースに保存する。
FR-003	内容の変更	最新のトレンドランキング TOP20 を表示し、前回からの順位の変動を矢印で示す	最新のトレンドランキング TOP20 を表示し、前回からの順位の変動を矢印で示す。どの順位も背景解説を開ける。
3. 選択肢

この節は、変更の進め方の案です。案ごとに変える要件と結果が違います。1つを選んで合意してください。 おすすめは案1です。理由: 定例の打ち合わせで指摘された不整合を根本から解決し、すべてのランキング項目で解説を利用できるようにするため。

案1 すべてTOP20に拡張する案(おすすめ)
要件 ID	変更の種類	変更後の案
FR-001	内容の変更	12時間ごとにX APIから日本国内のトレンドランキングTOP20を取得する定期バッチ処理を実装する。
FR-002	内容の変更	トレンド取得と同時にLLMを用いて上位20件分の背景解説を自動生成しデータベースに保存する。
FR-003	内容の変更	最新のトレンドランキング TOP20 を表示し、前回からの順位の変動を矢印で示す。どの順位も背景解説を開ける。

結果: 取得件数とLLMの解説生成、ランキング表示のすべてをTOP20で統一するため、指摘された不整合が完全に解消されます。ただし外部APIの呼び出しやLLMの生成処理が増えるため、システムへの影響範囲が広くなります。

案2 取得と解説を据え置く案
要件 ID	変更の種類	変更後の案
FR-003	内容の変更	最新のトレンドランキング TOP10 を表示し、前回からの順位の変動を矢印で示す。どの順位も背景解説を開ける。

結果: 表示件数を10件に戻すことで取得や解説の仕組みを変更する必要がなくなり、手間を抑えられます。ただし画面でTOP20を見たいという要望は満たせなくなります。

案3 取得は20件にそろえ、解説は上位10件のままにする案
要件 ID	変更の種類	変更後の案
FR-001	内容の変更	12時間ごとにX APIから日本国内のトレンドランキングTOP20を取得する定期バッチ処理を実装する。
FR-003	内容の変更	最新のトレンドランキング TOP20 を表示し、前回からの順位の変動を矢印で示す。背景解説は上位10件だけで、11〜20位には「解説はありません」と示す。

結果: 取得と表示はTOP20にそろいますが、背景解説の自動生成は今と同じ上位10件のままなので、LLMの利用料は増えません。11〜20位は解説を開けず、「解説はありません」と出ます。
