# 2. 外部設計書

## 2.1 システム構成概要
本システムは、ユーザーのブラウザからのリクエストをNginxを介して受け付け、フロントエンド（Next.js）およびバックエンド（FastAPI）へルーティングする構成をとる。バックエンドではLangChain/LangGraphを用いたAI対話制御およびGemini Flash-Lite APIとの連携を行い、非同期処理結果をPostgreSQLに永続化、セッション管理やレート制限をRedisで制御する。

```text
[User / Browser]
       │
       ▼ (HTTPS / SSE)
   [ Nginx ]
       │
       ├─> [ Next.js (Frontend) ]  (App Router + Tamagui)
       │         │
       │         ▼ (REST API / JWT)
       └─> [ FastAPI (Backend) ]   (Python 3.13 + LangChain/LangGraph)
                 │
                 ├─> [ Gemini Flash-Lite API ] (LLM & PDF Text Extraction)
                 ├─> [ PostgreSQL ] (Users, Projects, Chats, Documents v1-3)
                 └─> [ Redis ]      (Rate Limiting & Token Blacklisting)
```

## 2.2 画面一覧・画面遷移フロー（概要）

### 画面一覧
| 画面ID | 画面名 | 主要な役割 | 優先度 |
|:---|:---|:---|:---|
| SCR-001 | ログイン画面 | メール・パスワードによる認証を行う | Must |

## 2.3 主要画面のUI/UX仕様

### SCR-004: プロジェクト作成・資料アップロード画面
- **入力項目**:
  - プロジェクト名（テキスト入力、必須）
  - プロジェクト概要・アイデア（テキストエリア、必須）
  - 参考資料（ファイルアップロード、txt / md / pdf、最大3件まで）
- **表示項目**:
  - アップロードされたファイルの一覧（ファイル名、サイズ、削除ボタン）
- **操作ボタン**:
  - 「キャンセル」ボタン（ダッシュボードへ戻る）
  - 「ヒアリングを開始する」ボタン（バリデーション通過後にアクティブ化）
- **アクション**:
  - ファイル形式・サイズ・件数のクライアントサイドバリデーション。
  - フォーム送信後、プロジェクトを作成し、SCR-005へ遷移。

### SCR-005: AIヒアリングチャット画面
- **入力項目**:
  - チャットメッセージ入力欄（テキストエリア、送信キーバインド対応）
- **表示項目**:
  - チャット履歴エリア（ユーザーとAIのメッセージ、SSEによるリアルタイムストリーミング表示）
  - 5つの必須観点（目的、ターゲット、機能、非機能、制約）ごとの構造化サマリ進捗パネル
  - ヒアリング完了時：承認確認モーダルまたはサマリカード
- **操作ボタン**:
  - 「送信」ボタン
  - 「サマリを承認して設計書を生成する」ボタン（全観点充足またはユーザー判断で活性化）
- **アクション**:
  - メッセージ送信時にSSE接続を開始し、AIの回答を逐次描画。
  - 承認ボタン押下によりバックエンドへ設計書生成トリガーを送信し、SCR-006へ遷移。

### SCR-006: 設計書生成・プレビュー画面
- **表示項目**:
  - タブ切り替えメニュー（要件定義書 / 外部設計書 / 内部設計書 / 実装計画）
  - 選択中設計書のMarkdownプレビューエリア
  - 自己診断結果パネル（最重要・中程度・軽微の3段階で不足点・改善案を表示）
  - バージョン選択セレクトボックス（直近3件のバージョン切り替え）
- **操作ボタン**:
  - 「クリップボードにコピー」ボタン
  - 「Markdownダウンロード」ボタン
  - 「自己診断を実行・再評価」ボタン
  - 「プロジェクト一覧へ戻る」ボタン
- **アクション**:
  - バックエンドの非同期生成状況をポーリングまたはWebSocket/SSEで監視し、生成完了次第プレビューを更新。
  - コピーボタン押下でクリップボードへMarkdownテキストを格納。

## 2.4 外部システム・API連携仕様

- **Gemini Flash-Lite API**
  - **連携目的**: チャットの対話生成、PDFファイルからのテキスト抽出、4種の設計書自動生成、自己診断処理。
  - **認証方式**: APIキー認証（環境変数にてサーバーサイドで安全に管理）。
  - **データ連携タイミング**: ユーザーからのチャット送信時、資料アップロード時のPDF解析時、ヒアリング完了後の設計書生成・自己診断バッチ実行時。

## 2.5 データ入出力仕様

### ファイル入出力仕様（参考資料アップロード）
- **受付フォーマット**: `.txt`, `.md`, `.pdf`
- **制限事項**: 最大3ファイルまで、1ファイルあたりの上限サイズは10MB。
- **バリデーションルール**:
  - 拡張子が `txt`, `md`, `pdf` のいずれかであること。
  - 合計ファイル数が3件を超えていないこと。
  - PDFの場合、Geminiのファイル理解機能へ適切に渡せる破損のないファイルであること。
