システム概要：Devex: AI との対話型チャットでユーザーのアイデアや要望をヒアリングし、「要件定義」「外部設計」「内部設計」「実装計画」の4種の Markdown 設計書を自動生成する Web アプリ。システム開発の初期フェーズで、ドキュメント作成の工数と属人化を減らしたい。

実現したい事：- チャットでヒアリングし、4種の設計書を一括生成する(MVP)
- 生成後に AI が各文書の不足点を3段階(最重要/中程度/軽微)で自己診断して提示する
- 生成した Markdown をプレビュー・コピー・ダウンロードできる
- 参考資料(txt/md/pdf、最大3件)を初期入力で読み込める
- ユーザー・チャット履歴・生成文書を PostgreSQL に保存する

対話フローは、AI 側が主導して質問する形を想定しています。初期入力(システム概要・実現したい事・参考資料)を読んだ AI が、不足している観点を1つずつ質問し、ユーザーの回答を深掘りします。ユーザーが自由に補足してもよいです。ヒアリングの完了は、目的・ターゲットユーザー・主要機能・非機能要件・制約の5つがそろったかを AI が判定し、そろったら構造化サマリを出してユーザーの承認を得てから生成に進みます。

テンプレートは、MVP では固定の見出し構成(要件定義・外部設計・内部設計・実装計画)で生成します。プロンプトテンプレートの選択(Webアプリ向け・API向けなど)は Should として後回しにします。

認証は MVP に含めます(メールとパスワードの JWT 認証。アクセストークン30分・リフレッシュトークン14日、リフレッシュは HttpOnly Cookie)。バージョン管理は、DB でバージョンを増やして直近3件を保持する仕組みまでを MVP に入れ、履歴の閲覧・比較・復元の画面は Should にします。

1. 想定ユーザーは、システムエンジニア・IT コンサルタント・プロジェクトマネージャーと、個人開発者・スタートアップの創業者です。使う場面は、新規プロジェクトの立ち上げでアイデアを構造化した設計書にしたいとき、クライアントのヒアリング内容から初期ドキュメントのドラフトを素早く作りたいときです。

2. 対象システムの技術スタックは、チャットの中でユーザーからヒアリングして反映します。ユーザーが決めていなければ、AI が一般的な構成を提案して確認します。

なお、Devex 自体の技術スタックと制約は次のとおりです。
- フロントエンド: Next.js(App Router)+ Tamagui。バックエンド: FastAPI + LangChain/LangGraph(Python 3.13)。DB: PostgreSQL、レート制限とトークン失効に Redis。Docker Compose で動かし、VPS に nginx 経由でデプロイします。
- LLM は Gemini Flash-Lite(無料枠想定)。無料枠の上限を超えたときのエラーをエラーハンドリングに組み込みます。
- 非機能: チャットはストリーミング(SSE)で返す。4文書の一括生成はタイムアウトを防ぐためバックグラウンドの非同期処理にする。フォームのラベル関連付けやキーボード操作などのアクセシビリティに対応する。
- 対象外: 設計書からのコード自動生成、Jira・Notion などへの連携、マルチテナントの権限管理、音声入力、複数人の同時編集。

ヒアリングの内容をまとめました。

新規プロジェクトの立ち上げや初期ドキュメントのドラフト作成を目的とし、SE・ITコンサル・PM・個人開発者・スタートアップ創業者を対象に、AIチャットによるヒアリングと4種の Markdown 設計書の自動生成を行う Web アプリ（Devex）の要件が整いました。MVPスコープとして、メール/パスワードのJWT認証、DBでの3世代バージョン管理、初期の参考資料（txt/md/pdf・最大3件）のコンテキスト統合、Gemini Flash-Liteの無料枠考慮、SSEストリーミングとバックグラウンド非同期生成、アクセシビリティ対応を含み、コード自動生成や外部ツール連携等は対象外とします。技術スタックは Next.js(App Router)+Tamagui、FastAPI+LangChain/LangGraph(Python 3.13)、PostgreSQL、Redis、Docker Compose、Nginx（VPSデプロイ）で合意済みです。
