# 2. 外部設計書

## 2.1 システム構成概要
本システムは、モダンなWeb技術とコンテナ化アーキテクチャを採用し、スケーラビリティと保守性を担保した構成としています。

```text
[ ユーザー (ブラウザ) ]
       │ HTTPS / SSE (リアルタイム通信)
       ▼
 [ VPS / Nginx (リバースプロキシ / SSL終端) ]
       │
       ├─────────────────────────────────┐
       ▼                                 ▼
 [ Next.js (Frontend) ]           [ FastAPI (Backend) ]
 (App Router / Tamagui)           (Python 3.13 / LangGraph)
                                         │
            ┌────────────────────────────┼────────────────────────────┐
            ▼                            ▼                            ▼
     [ PostgreSQL ]                 [ Redis ]                 [ Gemini API ]
 (ユーザー / チャット履歴 /       (レート制限 / トークン管理 /       (LLM: Flash-Lite)
    設計書バージョン)               非同期ジョブ制御)
```

- **フロントエンド層 (Next.js)**: App Routerによるサーバーコンポーネントとクライアントコンポーネントの最適配置。Tamaguiを用いたクロスプラットフォーム対応のUIコンポーネント群。
- **バックエンド層 (FastAPI)**: Python 3.13による高速な非同期APIサーバー。LangGraphを用いたマルチステップのエージェント処理（ヒアリング・4種設計書生成）を制御。
- **データ・キャッシュ層**:
  - **PostgreSQL**: ユーザー情報、チャットセッション、生成された4種設計書（直近3件のバージョン管理）を永続化。
  - **Redis**: APIレート制限（Rate Limiting）、JWTリフレッシュトークンの失効管理、セッションキャッシュ。
- **外部AI層**: Google Gemini API (Flash-Lite) を活用し、コストと速度を最適化したテキスト生成・ストリーミング処理を実現。

## 2.3 主要画面のUI/UX仕様

### SCR-003: ダッシュボード画面
- **入力項目**: 
  - 検索窓（プロジェクト名・キーワード検索）
- **表示項目**: 
  - ユーザー名・アイコン、ログアウトボタン
  - 過去のプロジェクト一覧カード（プロジェクト名、作成日時、ステータス: 進行中/完了、最新バージョン）
- **操作ボタン**: 
  - 「新規プロジェクト作成」ボタン（Primary）
  - 各プロジェクトカードクリック（詳細・設計書閲覧画面へ遷移）
- **アクション**: 
  - プロジェクト一覧の取得（ページネーション対応）、プロジェクト削除

### SCR-004: 新規プロジェクト作成画面
- **入力項目**: 
  - プロジェクト概要・アイデア（テキストエリア、必須）
  - 実現したいこと・目的（テキストエリア、必須）
  - 参考資料アップロード（ファイル選択 / ドラッグ＆ドロップ、対応形式: `.txt`, `.md`, `.pdf`、最大3件まで）
- **表示項目**: 
  - アップロード済みファイル名一覧（削除ボタン付き）
  - バリデーションエラーメッセージ（ファイル形式・サイズ超過時）
- **操作ボタン**: 
  - 「ヒアリングを開始する」ボタン（Primary）
  - 「キャンセル」ボタン（Secondary）
- **アクション**: 
  - 参考資料のバリデーション・一時保存、チャットセッションの初期化と `SCR-005` への遷移

### SCR-005: ヒアリングチャット画面
- **入力項目**: 
  - ユーザーからの回答・追加要望入力フィールド（テキストエリア、キーボード `Cmd/Ctrl + Enter` で送信対応）
- **表示項目**: 
  - チャット履歴エリア（AIの質問とユーザーの回答を時系列表示、スクロール追従）
  - SSEによるAI回答のストリーミングリアルタイム表示
  - 現在のヒアリング進捗インジケーター（5観点の充足度合を視覚化）
- **操作ボタン**: 
  - 「送信」ボタン（Primary）
  - 「サマリを確認する（手動完了）」ボタン（Secondary）
- **アクション**: 
  - メッセージ送信API呼び出し、SSEストリーム受信処理、5観点充足判定による `SCR-006` への自動または手動遷移

### SCR-006: サマリ承認画面
- **入力項目**: 
  - 特になし（確認のみ。修正がある場合はチャットに戻る）
- **表示項目**: 
  - AIが整理した構造化サマリ（プロジェクト概要、主要機能、ターゲット層、技術スタック等の構造化表示）
- **操作ボタン**: 
  - 「この内容で設計書を生成する」ボタン（Primary）
  - 「チャットに戻って追加ヒアリングを行う」ボタン（Secondary）
- **アクション**: 
  - 承認APIの呼び出し、4種設計書生成の非同期バックグラウンドジョブ発火、`SCR-007` への遷移

### SCR-008: 設計書閲覧・編集画面
- **入力項目**: 
  - タブ切り替え（「要件定義」「外部設計」「内部設計」「実装計画」）
- **表示項目**: 
  - 選択中タブのMarkdownプレビュー表示エリア
  - AI自己診断パネル（不足点・改善提案を「最重要」「中程度」「軽微」の3段階で表示）
  - バージョン選択ドロップダウン（直近3件の履歴切り替え）
- **操作ボタン**: 
  - 「Markdownをコピー」ボタン（クリップボードへコピー）
  - 「Markdownダウンロード」ボタン（`.md`ファイルとして端末へ保存）
  - 「ダッシュボードに戻る」ボタン
- **アクション**: 
  - 設計書データ取得、バージョン切り替え、クリップボードコピー、ファイルダウンロード

## 2.4 外部システム・API連携仕様

### 2.4.1 Google Gemini API (Flash-Lite)
- **連携目的**: AIチャットの質問生成、5観点判定、および4種設計書の順次生成。
- **認証方式**: APIキー認証（環境変数 `GEMINI_API_KEY` による管理）。
- **データ連携タイミング**: 
  - チャットメッセージ送信時（リアルタイムSSEストリーミング）
  - サマリ生成時
  - 承認後のバックグラウンド非同期一括生成時
- **エラーハンドリング**: 
  - 無料枠上限超過（Rate Limit / Quota Exceeded）検知時は、ユーザーに対して「AIの利用制限に達しました。しばらく経ってから再度お試しください」というトースト通知および適切なHTTPステータス（503 Service Unavailable）を返却。

## 2.5 データ入出力仕様

### 2.5.1 参考資料ファイルアップロード
- **受付フォーマット**: `.txt`, `.md`, `.pdf`
- **制限事項**: 最大3件まで、1ファイルあたりの最大サイズは 10MB。
- **バリデーションルール**:
  - 拡張子チェック (`.txt`, `.md`, `.pdf`)
  - MIMEタイプチェック (`text/plain`, `text/markdown`, `application/pdf`)
  - 制限件数超過バリデーション（4件目以降はエラー返却）

### 2.5.2 Markdown設計書ダウンロード
- **出力フォーマット**: `.md` (UTF-8エンコーディング)
- **ファイルNaming規則**: `<project_id>_<document_type>_v<version>.md` (例: `proj_12345_requirement_v1.md`)
