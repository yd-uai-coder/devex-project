実装前提・制約

技術スタック・開発環境(段階7)

DockerおよびDocker Composeを用いたローカル開発環境を構築する。PythonおよびFastAPIを採用し、データベースにはPostgreSQLを使用する。自動テストはpytestを用いた単体テストおよび結合テストを実施する方針とする。

実装ルール(段階4・07章より)

  • モジュールは、段階4のモジュール一覧の依存先にだけ依存する(層を飛び越さない)。
  • 07章 例外: 発生した例外は app.py の例外変換機構で捕捉し、共通の JSON 形式のエラーレスポンスに変換する。検証エラーは 400 Bad Request、存在しないリソースへのアクセスは 404 Not Found、予期せぬシステムエラーは 500 Internal Server Error に対応させる。
  • 07章 HTTP: API のルーティングとリクエスト・レスポンスはすべて FastAPI を用いて実装する。データ構造のバリデーションには Pydantic モデルを使用し、成功時のステータスコードは新規作成が 201 Created、取得・成功が 200 OK とする。
  • 07章 認証: 本人以外が他人のプロジェクトを見られないようアクセス権限を管理する。認証に関する具体的な実装およびトークンの有効期限については (要決定) とする。
  • 07章 トランザクション: データベースの書き込みを伴う複数の操作(プロジェクト作成や文書生成など)は、サービス層で一つのトランザクションとして管理する。処理が成功した場合はコミットし、例外が発生した場合はロールバックする。
  • 07章 ログ: 開発者自身がエラーログや死活監視ツールの通知メールで異常に気づけるよう、エラー発生時にはタイムスタンプ、処理ID、エラー内容、トレースバックをログに出力する。また、外部サービスの呼び出しエラーやシステム異常を適切に記録する。
