# M-05-T01 設計書・診断結果の取得APIとNext.jsフロントエンドのUIを実装する

> 種別: 機能 / マイルストーン: M-05 文書プレビュー・ダウンロードとデータ取得API / 要件: FR-004, FR-006 / 依存: M-04-T01

## 目的

設計書および診断結果を取得するバックエンドAPIと、それを表示するNext.jsフロントエンドのUIを実装する。

## 対象の処理・参照する設計

- 内部設計書 DF-004 GET /api/v1/projects/{id}/documents
- 内部設計書 3.3 `backend/app/api/v1/endpoints/documents.py`

## 作成・変更するファイル(依存順)

| ファイル | 種類 | 責務 | 根拠 |
|---|---|---|---|
| `frontend/package.json` | 環境・設定 | フロントエンドの依存パッケージを定義する | 環境・設定のファイル |
| `frontend/next.config.js` | 環境・設定 | Next.jsの設定を定義する | 環境・設定のファイル |
| `backend/app/api/v1/endpoints/documents.py` | モジュール | 設計書・診断結果の取得APIエンドポイントを提供する | 内部設計書 3.3 |
| `frontend/components/DocumentViewer.tsx` | モジュール | 設計書および診断結果を表示するUIコンポーネントを提供する | 内部設計書 3.3 |
| `frontend/app/projects/[id]/page.tsx` | モジュール | プロジェクト詳細画面として設計書と診断結果のビューを統合する | 内部設計書 3.3 |

## 実装の要点(設計に書いていないことだけ)

- バックエンドのエンドポイント実装後にフロントエンドからのフェッチ処理を実装する順序とする。

## テスト観点

| # | 観点 | SUT | ドライバ | スタブ |
|---|---|---|---|---|
| TC-01 | 指定されたプロジェクトIDの設計書および診断結果が正しく取得できること | GET /api/v1/projects/{id}/documents | 手動テスト (curl / Postman) | スタブ不要 ── 実際のデータベース接続を利用して検証する |

- Given: 対象プロジェクトの設計書と診断結果がデータベースに存在する
- When: GET /api/v1/projects/{id}/documents にリクエストを送信する
- Then: 該当する設計書データおよび診断結果のJSONレスポンスが返却される

## 確認方法

- curlまたはPostmanを使用してAPIエンドポイントへリクエストを送り、期待されるJSONが返却されることを確認する。
- Next.jsのフロントエンド画面を開き、設計書と診断結果が正しく表示されることを目視で確認する。
