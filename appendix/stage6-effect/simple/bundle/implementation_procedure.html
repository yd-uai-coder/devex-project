実装前提・制約

技術スタック・開発環境(実装計画書 4.3・内部設計書 3.1)

### ### 1. 開発に必要なツール・技術スタック - **言語・ランタイム**: Python 3.13, Node.js (LTS) - **コンテナ技術**: Docker, Docker Compose - **データベース**: PostgreSQL, Redis - **外部AI**: Google Gemini API (Flash-Lite) ### ### 2. リポジトリ構成 ```text / ├── backend/ # FastAPIバックエンド ├── frontend/ # Next.jsフロントエンド ├── nginx/ # Nginx設定ファイル ├── .github/workflows/ # GitHub Actions CI/CD設定 └── docker-compose.yml # 統合Docker Compose定義 ``` ### ### 3. 自動テスト・CI/CD方針 - **テスト方針**: MVPフェーズでは自動テストコードの作成は後回しとし、APIエンドポイントの動作確認（Postman/curl等）を中心に手動テストで品質を担保する。 - **CI/CD方針**: mainブランチへのプッシュをトリガーとして、GitHub ActionsによりVPS上のDocker Compose環境へ自動ビルドおよびコンテナ再起動（デプロイ）を行う。 - **フロントエンド**: Next.js (App Router) + Tamagui - 選定理由: SSRによる初期表示の高速化、UIコンポーネントの一貫性とクロスプラットフォーム対応が容易なTamaguiを採用。 - 構成方針: ページ単位のルーティングをApp Routerで構成し、状態管理はReact HooksおよびContext APIを利用する。 - **バックエンド**: FastAPI + LangChain・LangGraph (Python 3.13) - 選定理由: 非同期処理に強く、AIエージェントの構築・ステート管理に優れたLangGraphおよび高速なFastAPIを採用。 - 構成方針: レイヤードアーキテクチャ（ルーター・サービス・リポジトリ層）を採用し、ビジネスロジックとデータアクセスを分離する。 - **データベース**: PostgreSQL - 選定理由: リレーショナルデータ（プロジェクト、チャット履歴、生成文書）の堅牢な管理とJSONB等による柔軟な拡張性のため。 - **インフラ**: VPS + Docker Compose + nginx - 選定理由: コストパフォーマンスが高く、コンテナ化により環境差異を排除したデプロイを実現するため。nginxをリバースプロキシとして前段に配置し、SSL終端および静的ファイル配信を担当する。
