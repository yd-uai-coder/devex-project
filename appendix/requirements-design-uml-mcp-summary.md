# 要件定義・設計書テンプレートとUML MCPの要点

## 結論

- IPAには、要件定義の成果物例、非機能要件を整理するための資料・Excel活用シート、設計書の教育用サンプルがある。
- 「要件定義書をそのまま作れる包括的な雛形」に近いものは、IPAより**デジタル庁の標準ガイドライン付属テンプレート**である。
- 個人開発では公的資料を網羅性チェックの基準にし、実際のドキュメントはMarkdown、OpenAPI、Mermaid/PlantUML、DBマイグレーション、テストへ分散させるのが実務的。
- UMLについてはMCPサーバーがあり、第一候補は公式PlantUML系の`@plantuml/mcp-js`。ローカルでAIにPlantUMLを生成・検証・レンダリングさせられる。

## 公的なテンプレート・参照先

### デジタル庁：デジタル社会推進標準ガイドライン

最も雛形に近い資料。各種テンプレート群には、以下が含まれる。

- 要件定義書標準テンプレート
- 調達仕様書標準テンプレート
- 業務要件・機能要件・非機能要件の記載の型
- データ、移行、運用、セキュリティ、アクセシビリティ等の観点

政府情報システム向けのため個人開発には重い。章立て・観点だけを採用し、不要部分を「対象外」または「将来対応」として明記して軽量化する。

### IPA：非機能要求グレード 2018

要件定義で特に有用。PDFとExcel形式があり、非機能要件の抜け漏れを防ぐために使える。

主な観点：

- 可用性
- 性能・拡張性
- 運用・保守性
- 移行性
- セキュリティ
- システム環境

LLMを使うWebアプリでは、通常の非機能要件に加えて、LLMのタイムアウト、レート制限、利用量・料金上限、プロンプトインジェクション、外部API障害時のフォールバックを明示する。

### IPA：要件定義の成果物事例

「超上流から攻めるIT化の事例集」では、要件定義・RFPなどの成果物例を参照できる。コピペ用テンプレートというより、成果物の分け方と記載粒度を知るための資料。

## 個人開発向けドキュメント構成

`docs/`配下で、次の8ファイル程度から始める。

| ファイル | 主な工程 | 内容 |
|---|---|---|
| `01_product-requirements.md` | 要求・要件定義 | 背景、課題、対象ユーザー、成功指標、スコープ外 |
| `02_functional-requirements.md` | 要件定義 | ユースケース、機能一覧、受入基準、優先度 |
| `03_nonfunctional-requirements.md` | 要件定義 | 性能、可用性、セキュリティ、運用、コスト |
| `04_system-architecture.md` | 外部／基本設計 | 構成図、外部API、認証、データフロー |
| `05_screen-spec.md` | 外部／基本設計 | 画面一覧、画面遷移、入力・表示・バリデーション |
| `06_api-spec.yaml` | 外部／基本設計 | OpenAPI仕様 |
| `07_data-model.md` | 基本〜詳細設計 | ER図、テーブル定義、保持期間、個人情報区分 |
| `08_internal-design.md` | 内部／詳細設計 | モジュール責務、シーケンス図、例外処理、リトライ、LLM/RAGフロー |

### 設計書を重くしない原則

- 外部設計：利用者・フロントエンド・外部連携先と合意する仕様
- 内部設計：実装者がコードに落とすための仕様
- API仕様はOpenAPIを正本にする
- DB仕様はORM定義・migrationを正本に近づける
- 図はPlantUMLまたはMermaidをテキストとしてGit管理する
- テストを受入基準・実装仕様の一部として扱う

## 設計資料を参照するMCP

IPA・デジタル庁の資料だけを公式かつ常時最新で検索する定番MCPは、確認できなかった。

推奨方針：

1. GitHub MCPで公開テンプレート、ADR、C4、OpenAPI、SRSなどを検索する
2. IPA・デジタル庁の資料と自作テンプレートをRAGに取り込む
3. FastMCPやMCP SDKで、読み取り専用の「設計標準RAG MCP」を自作する

自作MCPのTool例：

```text
search_design_standard(query, document_type?, phase?)
get_template(template_id)
get_checklist(topic)
review_requirement_document(markdown, checklist="ipa-nfr")
generate_project_docs(project_type, stack, constraints)
```

## UML用MCPサーバー

### 第一候補：`@plantuml/mcp-js`

- PlantUML公式系のNode.jsローカルMCP
- Java不要、外部PlantUMLサーバー不要
- AIからPlantUMLの生成、構文検証、レンダリングに使える
- シーケンス図、クラス図、状態遷移図、ユースケース図、コンポーネント図、配置図などに向く

概念的な設定例：

```json
{
  "mcpServers": {
    "plantuml": {
      "command": "npx",
      "args": ["-y", "@plantuml/mcp-js"]
    }
  }
}
```

実際の設定場所・登録方法は、Claude Code、Cursor、VS Code、CodexなどのMCPクライアントごとに異なる。

### 多形式対応：`uml-mcp`

PlantUMLに加え、Mermaid、D2、Krokiを扱える選択肢。UML以外にもC4、BPMN、ERD、Graphviz系などを扱いたい場合に向く。設計情報を外部HTTPサービスに送信する構成では、送信先・ログ保存・認証・公開範囲を確認する。可能ならローカル版を優先する。

### PlantUML Server連携型

既存のPlantUML ServerをDockerなどで運用し、チーム共通のレンダリング環境を使いたい場合は、PlantUML Server連携型のMCPが選択肢になる。個人開発では、まずローカルNode.js版で十分。

## UML図と設計工程の対応

| 図 | 主な配置先 | 内容 |
|---|---|---|
| ユースケース図 | 要件定義書 | 誰が何を実現するか |
| アクティビティ図 | 要件定義書／外部設計書 | 業務・利用者操作の流れ |
| 画面遷移図 | 外部設計書 | UI遷移・画面状態 |
| シーケンス図 | 外部・内部設計書 | API、認証、外部API、例外処理 |
| クラス図 | 内部設計書 | ドメインモデル・モジュール責務 |
| コンポーネント図 | 外部設計書 | フロント、API、DB、LLM、ベクトルDB等の関係 |
| 配置図 | 外部設計書／運用設計書 | クラウドサービス・ネットワーク配置 |
| 状態遷移図 | 外部・内部設計書 | セッション、ジョブ、課金、認証の状態 |

## LLM/RAGアプリで優先する図

最初に以下の3つを作るとよい。

1. 認証シーケンス図：ログイン、セッション更新、失効、認可失敗
2. RAG検索シーケンス図：入力検証、クエリ変換、検索、再ランキング、LLM呼出、引用、フォールバック
3. 利用量・課金制御の状態遷移図：通常利用、警告、制限、翌月リセット、管理者解除

## 推奨する開始手順

1. デジタル庁の要件定義書標準テンプレートを確認し、必要な章だけ採用する
2. IPA非機能要求グレードから必要項目を選び、`03_nonfunctional-requirements.md`を作る
3. 上記の軽量ドキュメント構成をGitリポジトリの`docs/`に作成する
4. `@plantuml/mcp-js`をローカル導入する
5. `.puml`を`docs/diagrams/`に置き、Markdownから参照する
6. OpenAPI、migration、IaC、テストを可能な範囲で仕様の正本に近づける
7. 公的資料と自作テンプレートを取り込んだ、検索専用RAG MCPを必要に応じて作る
