# 要件 → 処理 → 作業単位(見本)

[README](./README.md) の見本。[Phase 33-2](../../textbook/Phase-33/Phase-33-2.md) 決定4・7の追跡を、題材で示す。処理(F-xx)と作業単位(M-xx-Txx)は、ベースラインの詳細設計モードの段階1・段階7([`stage6-baseline/detailed/stages/`](../stage6-baseline/README.md))を使い、要件ID は [requirements.md](./requirements.md) のものを当てた(ベースラインの段階1は要件ID を持たないので、この対応は手で付けた)。

## 詳細設計モード: 段階1の `req_ids` から導く

段階1の機能の行に `req_ids` を持たせる。作業単位は段階7の `function_ids` から導くので、新しく持たせるものは段階1の列だけ。

| 要件 | 優先度 | 処理(段階1) | 作業単位(段階7) |
|---|---|---|---|
| FR-001 | Must | F-01 新規ユーザー登録、F-02 ログイン認証 | M-01-T02、M-01-T03 |
| FR-002 | Must | F-03 プロジェクト一覧取得、F-04 プロジェクト新規作成 | M-02-T01、M-02-T02 |
| FR-003 | Must | F-05 参考資料アップロード | M-02-T03 |
| FR-004 | Must | F-06 チャット履歴取得、F-07 ヒアリングチャットメッセージ送信 | M-02-T04、M-02-T05 |
| FR-005 | Must | F-08 構造化サマリ取得、F-09 サマリ承認・生成トリガー、F-10 進捗確認 | M-02-T06、M-03-T01、M-03-T02 |
| FR-006 | Must | F-11 設計書の一覧・最新版取得 | M-03-T03 |
| FR-007 | Must | F-14 自己診断結果取得 | M-04-T03 |
| FR-008 | Must | F-12 版一覧取得、F-13 追加修正による再生成 | M-04-T01、M-04-T02 |
| FR-009 | Must | **なし** | — |
| FR-010〜FR-012 | Should・Could | なし(今回の範囲外) | — |

### 検証が出す指摘(段階1)

| 重要度 | 指摘 | 例 |
|---|---|---|
| 中程度 | 処理の無い Must の機能要件 | FR-009(途中の失敗と再生成)を担う処理が無い。例外の場面を、既存の処理の分岐(段階5)で書くか、処理を足すかを決める |
| 軽微 | 要件の無い処理 | (例)F-15 管理者の統計画面 ── 要件定義書に無い機能を AI が足した |
| 軽微 | 要件定義書に無い要件ID | `req_ids` に `FR-099` |
| 軽微 | 要件ID が無い(既存のプロジェクト) | 要件定義書を再生成すると使える(決定8) |

非機能要件(NFR)と制約(CON)は処理に結ばない。段階7の横断事項(例外・認証・トランザクション・ログ)と、手順書の「実装前提・制約」に引き継ぐ(結び方は Phase の計画で決める)。

## 簡易モード: WBS の行の「要件」欄

実装計画書の WBS の決まった書式([Phase 31](../../textbook/Phase-31/Phase-31-introduction.md))に、「要件」の行を足す。

```markdown
### M-02: プロジェクトとヒアリング ── 【Must】
- [ ] M-02-T01 [機能] プロジェクトを作成し、参考資料を読み込む
  - 処理: DF-02
  - 要件: FR-002, FR-003
  - 依存: M-01-T02
  - モジュール: backend/app/services/project.py
```

解析(`simple_procedure/wbs.parse_wbs`)が「要件」を読み、段階8の単位の一覧に要件の列を出す。検証は詳細設計モードと同じ規則(処理の無い Must の機能要件 → 作業単位の無い Must の機能要件、と読み替える)。
