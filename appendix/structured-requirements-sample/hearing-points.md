# 観点の表(見本)

[README](./README.md) の題材(Devex 自身、[ペルソナ](../stage6-baseline/persona.md))で、改良後のヒアリングが終わった時点の観点の表。Claude が手で書いた。LLM の出力ではない。

## 1. 観点の定義(コードに持つ)

[Phase 33-2](../../textbook/Phase-33/Phase-33-2.md) 決定3・6。機能面の観点と、IPA の非機能要求グレードの6大項目。問いは「場面」で聞く(決定5)。

| キー | 種類 | 観点 | 場面で聞く問いの例 | 個人・小規模 | 社内 | 公開サービス |
|---|---|---|---|:---:|:---:|:---:|
| `scale` | 機能面 | 規模 | 使うのは自分(と数人)だけですか。社内の人ですか。誰でも登録できるサービスですか | 必須 | 必須 | 必須 |
| `purpose` | 機能面 | 目的・課題 | これが無いと、今は何に困っていますか | 必須 | 必須 | 必須 |
| `users` | 機能面 | 利用者と使う場面 | 誰が、どんなときに開きますか | 必須 | 必須 | 必須 |
| `daily_flow` | 機能面 | 利用者の1日の流れ | 使う人の1日のどこで、どのくらいの時間使いますか | 任意 | 必須 | 必須 |
| `core` | 機能面 | コア機能 | 最初の版で、これだけはできてほしいことは何ですか | 必須 | 必須 | 必須 |
| `scope` | 機能面 | MVP の範囲 | 最初の版で作らないと決めているものはありますか | 必須 | 必須 | 必須 |
| `exceptions` | 機能面 | 例外の場面 | 入力を間違えた・取り消したい・途中で失敗した・権限が無い、のときにどうなってほしいですか | 必須 | 必須 | 必須 |
| `future` | 機能面 | 将来の拡張 | 後で足したいと思っているものはありますか | 任意 | 任意 | 必須 |
| `tech` | 機能面 | 技術スタック・環境の制約 | 使いたい(使わなければならない)言語・フレームワーク・置き場所はありますか | 必須 | 必須 | 必須 |
| `schedule` | 機能面 | 体制・期間 | 何人で、いつまでに作りますか | 任意 | 任意 | 任意 |
| `availability` | 非機能 | 可用性 | 夜中や休日に止まっていたら、どのくらいで困りますか | 必須 | 必須 | 必須 |
| `performance` | 非機能 | 性能・拡張性 | 同時に何人くらいが使いますか。待てるのは何秒までですか | 必須 | 必須 | 必須 |
| `operability` | 非機能 | 運用・保守性 | 止まったことに、誰がどうやって気づけばよいですか | 任意 | 必須 | 必須 |
| `migration` | 非機能 | 移行性 | 今使っている仕組みやデータから、移すものはありますか | 任意 | 必須 | 必須 |
| `security` | 非機能 | セキュリティ | 入れたデータを、誰に見られたら困りますか | 必須 | 必須 | 必須 |
| `environment` | 非機能 | システム環境・エコロジー | どの端末・ブラウザで使いますか | 任意 | 必須 | 必須 |

- 規模(`scale`)が決まるまでは「個人・小規模」の列で数える。
- 「必須」は「未決のままでは完了にしない」の意味。「対象外」と決めれば済む。
- 完了の判定は、コードが「必須の観点がすべて未決以外」で決める(決定1)。LLM は、発言から観点ごとの状態と根拠を返すだけ。

## 2. 状態

| 状態 | 意味 | どうなったら |
|---|---|---|
| ユーザーが決定 | 利用者が自分の言葉で決めた | 自由に書いて答えた |
| AI の提案を採用 | AI が出した選択肢から利用者が選んだ | カードの選択肢を選んだ |
| 未決 | まだ決まっていない | 聞いていない、または「決めていません」 |
| 対象外 | この観点はこのシステムに要らないと決めた | 利用者がそう答えた |

## 4. 選択肢カードの例

カードは、AI の返信の後ろに付く構造化した問い(決定5)。選択肢を選ぶと、その観点は「AI の提案を採用」になる。自由に書いて答えると「ユーザーが決定」になる。

### 可用性

> **夜中や休日に Devex が止まっていたら、どのくらいで困りますか?**

| 選択肢 | 選んだ結果(コスト・手間) | |
|---|---|---|
| 半日〜1日止まっても困らない | 1台の VPS で足りる。止まったら手で戻す。費用は今のまま | おすすめ(個人の規模で、使うのは打ち合わせの後のため) |
| 1〜2時間で戻ってほしい | 死活監視と通知、戻す手順の整備が要る。手間が増える | |
| 止まると困る(業務で常に使う) | 2台以上やマネージド DB で冗長にする。費用が数倍になる | |

### セキュリティ(アクセス制御)

> **打ち合わせの内容を入れたプロジェクトを、誰に見られたら困りますか?**

| 選択肢 | 選んだ結果(コスト・手間) | |
|---|---|---|
| 自分以外の全員(本人だけが見られる) | ログインした本人のプロジェクトだけを返す。今の範囲で作れる | おすすめ(クライアントの情報が入るため) |
| 同じチームの人とは共有したい | 共有と権限の仕組みが要る。MVP の対象外(マルチテナント)に当たる | |
| 見られても困らない | 認可の確認を省ける。ただし、後から変えるのは難しい | |
