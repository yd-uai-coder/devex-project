# 構造化した要件定義の見本(Phase 33-3)

ステージ6(ヒアリング改良 + 上流の構造化)で Devex が作るもの ── 観点の表・選択肢カード・要件ID と出どころの付いた要件定義書・外部設計書の一覧・要件から作業単位までの追跡 ── の形を、実装の前に確かめるための見本。Claude が手で書いた。LLM の出力ではない。

- 題材: Devex 自身。[ステージ6のベースライン](../stage6-baseline/README.md) と同じ [ペルソナ](../stage6-baseline/persona.md) が、改良後のヒアリングに答えたら、という想定で書いた(潜在の事実 L1〜L14 が聞き出された状態)。
- 形: [Phase 33-2](../../textbook/Phase-33/Phase-33-2.md) の決定。
- 画面のデモ: devex-ui の `/hearing-points-demo`(同じ題材・同じ中身)。

## 読み方

- 要件の**出どころ**は3つ: ユーザー(利用者が決めた)/ 採用(AI の提案を利用者が選んだ)/ 推測(AI が補った。未確認)。ベースラインでは要件定義書の非機能・制約の6〜7割が、利用者が言っていない記述だった([Phase 33-1](../../textbook/Phase-33/Phase-33-1.md))。それが「推測」として見えるようにする。
- 観点の**状態**は4つ: ユーザーが決定 / AI の提案を採用 / 未決 / 対象外。必須の観点がすべて未決以外になったら、ヒアリングは完了。
- 要件ID は種別ごと(`FR-001`・`NFR-001`・`CON-001`)。
