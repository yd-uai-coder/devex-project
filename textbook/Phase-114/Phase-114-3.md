## 後の Phase への前提

- **Phase 115(CR の下書き・知らせ・規模)**: 選べる違いは `unconfirmed` の追加・変更・削除(確かめる点は選べない)。CR にした違いは `converted` にし、CR の番号を違いの表に足す(マイグレーション)。対象のキーは合意の要素のキーなので、CR の対象(要件の行)へは、要件なら `req:` を外し、画面・API・外部連携なら `req_ids` から候補を出す(111-4 の Phase 115 の未確定事項)。追加の起点が利用者と使う場面・外部連携のときの CR の起点のつなぎ方も決める(この Phase で起点を合意の要素のどれでもよいにしたため)。背景の出どころは資料の題と日付(`Material.title`・`material_date`)。取り出しの回の `freshness` が古ければ、CR の作成の知らせと同じ文を出せる。
- **Phase 116(画面)**: 一覧の応答(`extraction` の鮮度・`latest_baseline_number` と `extraction.baseline_number` の食い違い = 束を作り直した後)・違いの状態の表示(捨てた確かめる点は「閉じた」)・弾いた理由(`reasons`)。資料の一覧に違いの数を出すなら、そのときに一覧の応答へ足す。
- **Phase 117(効果測定)**: B-7 を作ってから、セット A・B を取り込みの API に各2回通す。この Phase の実 LLM の1回(introduction の検証結果)では、撤回(T1)を変更として挙げた回と挙げなかった回があった ── 決定的な検査では弾けない誤り(引用は文字どおりある)なので、効果測定の「(4) 撤回・済み・未決・言い換えを追加・変更・削除として出さない」で数える。マイグレーション `b8f3d6a2e915` の往復と、`OPERATIONS.md` 10.8節のステージ14 の分。
