1つ目のセッション:

2. **変更影響の合格の基準**(41-5 の未確定事項): **厳しめ**(推奨と違う。推奨は「過剰 ≤ 50%・見落とし ≤ 試案」)── S1〜S8 と N1〜N4 それぞれで、過剰の割合 ≤ 35%・見落とし ≤ 5(S)/ ≤ 1(N)・S2 の見落とし 0。

2つ目のセッション(直しの範囲。すべて推奨どおり):

5. **再生成の揺れ**: R1(差分の再生成)+ R2(単位のキーを重なりでも引き継ぐ)。R3(言い回しだけの差を無視)は入れない。
6. **たどり方**: B(テーブル → 処理を止める)・C(文書の変更で CRUD・作業単位・要約を示さない)・D(API → 入口のモジュール)・G(要件の変更は共有の画面で広げない)。E(横断事項 → 単位を止める)は S2 の見落としを増やすので入れない。
7. **S2 の扱い**: 範囲の外とし、判定から外す(ID の辺では届かない)。
8. **2・3回目の範囲**: 詳細は段階8 + 再生成、簡易は文書・段階8 + 再生成(別のプロジェクトでも直しを確かめる)。

Claude の判断(1つ目のセッション。計画の承認で確定):

- **ヒアリングの基準**: 側面の4観点が、必須の回のすべてで聞けたこと。自由回答の採用の幅がステージ6(詳細 0〜3・簡易 2〜4)を超えないこと。発言数は記録だけ。
- **段階3・5 の基準**: `DFD_WRITE_MISSING` 0・`MISSING_BRANCH_TARGET` 0・処理あたりの分岐の行がベースラインの半分未満に減らないこと。
- **再生成の印の正解は、印を取得する前に書く**。
- 47 の測定の回数(41-5 の未確定事項)は Phase 47 で各モード3回と決めてある。

実装中の判断:

- **判定は「実装(たどり方)」で行う**(ベースラインの4方式と同じく文書の要素も数える)。画面に出る「実装(印)」は参考として並べる([49-1](./Phase-49-1.md))。
- **文書の model はローカル DB から書き出した**(stage6-effect のプロジェクトが残っていた)。簡易モードの model の無い2文書は、段階8と同じ md の解析から作った。
- **章の順を計画から入れ替えた**: 1つ目のセッションの終わりには「49-3 ヒアリングのゆらぎ → 49-4 直し」と書いたが、直しを先にして(49-3)、2・3回目の実 LLM を直した本体で流した(49-4)。2・3回目の再生成で直しを確かめられるため(ヒアリングは直しの影響を受けない)。
- **R1 は「AI に印を付けさせ、システムが写す」**: 変えない行を `unchanged` と答えさせ、前の版の行で置き換える。手がかりとして、上流の文書で前の版から変わった行もシステムが求めて渡す([49-3](./Phase-49-3.md))。
- **D は層の名前でなく辺で**: 49-1 の試算は段階4の層の名前「入口」で決めたが、層の名前は構成図で決まり固定でないので、手順の最初の呼び出し先のモジュールから API への辺 `receives` にした。
- **C は簡易モードの軸のタスクを隠さない**: 49-1 の試算はこれも隠して N4 の見落としを1つ増やしていた。
- **タスクの内容の依存先をキーに読み替えた**(49-4 で見つけた): マイルストーンの並びが変わっただけのタスクが「変わったもの」になり、単位に印が付いていた。直す範囲を決めた R1 の狙い(頼んでいない変更で印を増やさない)の中の直しとして、Claude が判断して入れた([49-4](./Phase-49-4.md))。
