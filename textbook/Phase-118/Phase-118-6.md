## 1. spec

```ts
// e2e/guide-pages.spec.ts(抜粋)
import { GUIDE_FLOW, GUIDE_PAGES } from "../src/features/guide/guide-flow";
await page.getByRole("link", { name: "使い方を見る" }).click();
await page.getByRole("link", { name: `1. ${GUIDE_PAGES[GUIDE_FLOW[0]].title}` }).click();
for (const [index, slug] of GUIDE_FLOW.entries()) {
  await expectGuidePage(page, slug);          // 見出し・画像がすべて読める(naturalWidth > 0)
  // 帯の aria-current がこのページ → 「次へ」
}
```

- 画像は遅延読み込みなので、1枚ずつ画面に入れてから読み込みを確かめる。`next/image` の最適化を通して `public/guide` の WebP が返ることを、本番ビルドで確かめられる。
- 目次から開くリンクは、メニューにも同じ名前のリンクがあるので、「ページの一覧(流れの順)」の節の中で探す(初回はここで strict mode の違反になった)。
- スマホ幅(390px)で、帯が「段 8 / 全 9: 合意と変更」のボタンにたたまれ、押すと開くこと、横にはみ出さないことを確かめる。
- API は呼ばない(ログインの復元の確認だけ)ので、偽の LLM の設定によらず通る。

## 2. 流し方と結果

Phase 110・117 と同じ。ユーザーの `npm run dev`(3000 番)を止めずに流した。
- backend は、E2E のオーバーレイと、CORS に 3100 番を足す一時的な上書き(ジョブの作業用のディレクトリ)で立て直した。
- 画面は `NEXT_PUBLIC_E2E_FAKE_GOOGLE=true` でビルドして 3100 番で開き、`baseURL` だけを 3100 番にした一時的な設定で全 spec を流した。
- 結果: **16件成功**(既存14 + 新2。約4分)を2回。
- 流した後は 3100 番を止め、backend を通常の compose に戻し、通常のビルドを作り直した。一時的な設定は消した。
