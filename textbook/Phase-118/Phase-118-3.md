# Phase-118-3: 撮影用のデータと撮影

## この章の目的

GUIDE の「画面の見方」と TOP の Hero に載せるスクリーンショットを撮る。着手時の相談の決定(2)のとおり、撮影用の利用者とプロジェクトを新しく作り、実 LLM で一巡させてから撮る(個人情報・API キーが写らないように)。

自動実装モード: on([introduction](./Phase-118-introduction.md) 参照)。実装ファイルを作らない章(#13/#15 の対象外)。画像(`devex-ui/public/guide/*.webp`)は samples に写さない(#21 の「インフラ・設定」と同じく、コードでない素材のため)。

## 1. 撮り方

- 撮影の手順は、run-devex-ui スキルの `shot.mjs` と同じ Playwright(devex-ui の Chromium)で、ジョブの作業用のディレクトリに書いた手順のスクリプトで行った(リポジトリには入れない)。データを作る段(A〜G)と、載せる画像を撮る段(F)を分けた。
- 撮る段では、開発サーバーの印(左下の「N」。Next.js の開発用の表示)を CSS で隠し、ライトのテーマ・1280×800 の見える範囲で撮った(ヘッダー・フッターの固定の帯が重なる全体撮りはやめた)。
- PNG のままでは 5.5MB だったので、devex-ui の `sharp` で WebP にした。
- ヒアリングは、カードがあれば最初の選択肢を選び、用意した答え(利用者・範囲・認証・非機能)を送り、残りは「おまかせします」で、生成のボタンが出るまで繰り返した。

## 2. 載せなかったもの・撮れなかったもの

- **設計レビューの指摘**: 開発環境の `ANTHROPIC_API_KEY` が 401(invalid x-api-key)で、レビューは「失敗(自己診断に切り替え)」になった(前日までは成功)。キーはユーザーの管理なので触らず、この章では撮らなかった。ユーザーがキーを直した後に撮り足した([introduction](./Phase-118-introduction.md)「完了後の調整」)。
- **マイページの API キーの節**: 開発環境に暗号の鍵が無く「いまは API キーを登録できません」と出るので、載せずに文章で説明した(本番は登録できる)。
- **確認事項の一覧**: 撮影用のプロジェクトでは推測の要件・未決の観点が0件で空だったので、文章で説明した。
- CR-1 の反映の後、段階が「古い」になった状態で変更の影響のパネルを撮り(`dd-impact`)、その後に承認し直してから、詳細設計のほかの画面を撮り直した(古い状態のまま撮ると、ダウンロードが押せない画面になるため)。

## 3. 確かめたこと

- 個人情報: 撮影用の利用者のメールは `example.com`。クライアントの名前は架空(総務部 山田)。API キーは写っていない(マイページのキーの節は載せていない)。
- 実 LLM の費用: Gemini(gemini-3.5-flash-lite)だけで約60回。使用量の記録は無いので回数からの概算で $0.1〜0.3(計画の見込み $0.35〜0.95 の下。Claude のレビューは 401 で呼べず $0)。
