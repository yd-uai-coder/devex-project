### 読み取れること

1. **「論点」のような抽象語では、LLM は1つずつ確かめない**。対象の例を名指しすると、どの選択肢にも対象ごとの値が入った(h3)。Phase 59 の「コードが名指しすると効く」の続きで、名指しの粒度は「観点」より細かい「対象」まで下げるとよい。
2. **LLM の状態の判定には、コードの最後の守りが要る**(`decided` → `adopted`)。状態の意味(誰が決めたか)は、判定の文の読み違いでなく、根拠の発言(カードの答えだけ)から決まる。
3. **テストの義務は、設計にある事実から足すと当たる**(401 は他の API のエラー欄、LLM の上限は制約の行)。設計に無いもの(版の取得の API・献立1件の削除)は、義務を足しても当たらない。テスト仕様書でなく、設計の検証の問題(Phase 71 の範囲に近い)。
4. 簡易の当たりが変わらなかったのは、落ちた3件(TS-5・7・13)がいずれも設計に無いものだったため。
