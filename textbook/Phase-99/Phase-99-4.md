# Phase-99-4: 開発環境での画面確認と実 LLM の流れ

## この章の目的

Phase 97・98 から積んだ画面確認を、開発環境で行う。題材の「トレンド追跡アプリ」で実 LLM の流れ(合意 → 確認事項 → 再生成 → 影響が広がる CR → 段階 → 再生成)を通し、[99-1](./Phase-99-1.md) の測定の材料にする。操作はユーザーが画面で行った。

自動実装モード: on([introduction](./Phase-99-introduction.md) 参照)。

## この章で作成・更新したファイル

無い(確認の記録)。指摘の修正は [introduction](./Phase-99-introduction.md)「Phase 完了後の調整」。

| 操作 | 見込み | 実際(DB から) |
|---|---|---|
| 文書の再生成(要件 + 外部設計) | 3回・約 $0.03 | 2回(v10・v12) |
| CR の文書への反映 | 1回・約 $0.01 | 1回(v11) |
| 段階の作り直し | 1回・約 $0.01〜0.03 | 段階1 を CR-4 で2回、CR なしで1回 |
| 合計 | 約 $0.05・最大 約 $0.10 | 約 $0.05(単価で概算。トークンの記録は無い) |

## 流れの手順(ユーザーに示したもの)と実際

1. B-4 を作る。ステージ12 より前に反映した CR-3 が合意に入っていなかった(FR-001 が「8時間」のまま)。合意し直さないと、保護が CR-3 の変更を戻してしまう → 済み。
2. 確認事項で、推測の要件・利用者を確認済み、1件を却下、観点に決める機会を付ける → 済み(確認済み 12・却下 1・決める機会 8件)。
3. CR を渡さない再生成 → 済み(v10)。
4. CR-4(FR-003 を TOP20 にし、順位の変動を矢印で示す)を作り、説明・合意・文書への反映 → 済み(v11)。
5. 段階を CR-4 で作り直して承認 → 済み(段階1。結んだ印 40件)。
6. CR-4 の検証 → 行っていない(反映済みのまま)。
7. CR を渡さない再生成を2回 → 1回(v12)。

Claude は段ごとの書き出しを取れなかった。測定は、残っている版と、日時つきの合意の記録から組み直した(ユーザーの選択。[99-1](./Phase-99-1.md))。

## 画面確認の結果

| 項目(出どころ) | 結果 |
|---|---|
| 「合意の状態」の枠の長さ・印の色・履歴の行の言い方(Phase 97) | OK |
| CR の起点の選択の長さ・検証のタブの未承認の段階の節の位置(Phase 98) | OK |
| 確認事項の表の長さ・行の操作の並べ方・決めた記録の畳み方・推測の要件の枠のリンクの言い方(Phase 98) | **指摘**: 確認済みにしたものに、一覧から消えて別の表へ移るもの(推測の要件・利用者)と、同じ表に残るもの(観点)がある。移ったものは状態を変えられない |
| (確認中に見つかったもの) | **指摘**: CR-4 で段階1 を作り直した後に、機能一覧の「種別」のセレクトが狭く、選んだ値が見えない |
| 2回目の確認 | **指摘**: 機能グループのセレクトがまだ狭い。名称・トリガー・関連画面は狭くてよい。確認事項の「確認済み(採用して合意)」とリンクを2段に |
| 使い勝手(追加要求) | CR を詳細設計に反映した後、検証に届くまでの移動が多い。段階を進めるたびに前の段階に見直しが出る |

指摘と追加要求は、すべて Phase 完了後の調整で直した(introduction)。ユーザーは、Stage 9・10 と同じく、使い勝手を通して見て、後から直しを頼む可能性があると伝えた。
