# Phase 47 導入: ヒアリングの側面と判定のゆらぎ

## 目的

ステージ7(変更影響分析・変更管理)の6つ目の実装 Phase。変更管理とは主題が違うが、ステージ6の申し送りをこのステージで扱うと決めた([41-2](../Phase-41/Phase-41-2.md))。

ステージ6の効果測定([Phase 39](../Phase-39/Phase-39-introduction.md))では、潜在の事実のうち L2(バックアップ)・L5(ログに本文を残さない)・L6(不正利用)・L14(削除)が、どの回も聞かれなかった。原因は、1つの観点に問いが1つしかないため、可用性・セキュリティなどの2つ目の側面まで問いが届かなかったこと。また、自由回答が「採用」になる判定のゆらぎも残っていた。

この Phase では、側面を観点として足し(47-1)、ゆらぎを回の幅で数える道具を作る(47-2)。確定した仕様は [`docs/external_design.md`](../../docs/external_design.md) 2.10節「ヒアリングの側面(Phase 47 で確定)」と、[`docs/internal_design.md`](../../docs/internal_design.md) 3.3節「Phase 47 で足した部分」に足した。

## 着手時の相談で決めたこと

詳細は [`q_a.md`](../q_a.md) の「Phase 47 開始時」を参照。

1. **Phase 46 の完了後の調整・自動実装モード**: 調整なし・on(推奨どおり)。
2. **側面の方式(41-5 の未確定事項)**: 観点を足し、ラベルの先頭に大項目を付ける(推奨どおり)。ユーザーは最初、「観点の下に側面を構造化する案は変更が最も大きいとのことだが、それに見合うメリットがあるか」と再提案を求めた。両案を比べた結果、構造化にしかない利点は表を大項目でまとめて見せることだけで、DB・判定・カード・出どころ・API・画面のすべてが変わると分かり、観点を足す案を選んだ。
3. **規模ごとの必須(41-5 の未確定事項)**: 側面ごとに変える(推奨と違う。推奨は「社内以上で必須」)。データの保全と保持・削除は全規模、ログと不正利用は社内以上。
4. **L14 の置き場**: 運用・保守性の下(推奨と違う。推奨はセキュリティの下)。
5. **ゆらぎの測定の回数(41-5 の未確定事項)**: 各モード3回(推奨どおり)。Phase 47 では判定のコードは直さず、数える道具だけを作る。
