## 1. 必要なテストの件数(dev の DB、読み取りだけ、LLM なし)

外部設計書の model を持つプロジェクトに `required_tests` を流した。E2E の偽 LLM で作ったプロジェクト(API 2本・8件)を除く14件:

| モード | プロジェクト数 | API | 必要なテスト(結合 + 総合) |
|---|---|---|---|
| 詳細 | 6 | 4〜8 | 22〜38 |
| 簡易 | 8 | 4〜9 | 18〜39 |

- 異常(エラー欄の HTTP ステータスごと)が一番多く、次が非機能(非機能要件ごと)。
- 非機能要件の無い簡易の1件(`cc4a8df5`)は、API にも画面にも無い Must の要件の総合テストが2件出た。

## 2. 実 Gemini での生成(flash-lite、各1回)

`start_from="test_spec"` で、テスト仕様書だけを作った(4文書と段階は作り直していない。費用は無料枠)。

| プロジェクト | モード | 必要なテスト | 生成したテスト | 時間 | 検証の指摘 | 設計に無い |
|---|---|---|---|---|---|---|
| `33fdda56`(example-super-user の確認用) | 簡易 | 19 | 結合 15・総合 4 | 9.5 秒 | 0 | 2 |
| `86a37228`(ステージ7 効果測定の詳細) | 詳細 | 38 | 結合 28・総合 10 | 13.0 秒 | 0 | 9 |

- **件数**: どちらも必要なテストの一覧と同じ件数で、一覧の行をそのまま1件ずつ埋めた(縮まなかった)。
- **処理・単位**: すべての結合テストに入った(簡易は `DF-3 / M-02-T01` など、詳細は `F-01 / M-01-T02` など)。
- **設計に無い**: パスワード・プロジェクト名・チャットの上限文字数、他人のリソースへのアクセスのステータス(403 か 404 か)、未生成のサマリの承認のエラー、レート制限の値。見本(`test-spec.md`)の IT-005〜007・IT-008 と同じ種類の穴を、テストの形で出した。
- **見本との違い**: 見本では「FR-007(コピー)のテストが無い」が当たる想定だったが、実物では FR-007 が文書の一覧の API(`GET /projects/{id}/documents`)の要件にも入っているため、その API のテストで埋まり、`MUST_REQUIREMENT_UNTESTED` は出なかった。要件が API に結ばれていれば「テストがある」とみなすので、要件の中身(コピーとダウンロード)ごとのテストの抜けは決定的には見えない(introduction の申し送り。Phase 58 の正解例で数える)。
- **言語**: 簡易の1回目で、方針の「対象」の一部が英語だった(`… and NFR-001/… non-functional requirements`)。生成の規則に「日本語で書く(API のパス・項目名・値はそのまま)」を足した。足した後は実 Gemini で流していない。
