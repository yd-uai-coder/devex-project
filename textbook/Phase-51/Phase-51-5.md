| 59 | 統合/E2E・デプロイでの確認 | 偽 LLM の契約テスト(レビュー・採否・差し戻し)・既存を含めた全 E2E(#36)・マイグレーションの往復・本番反映の手順(`OPERATIONS.md`。`ANTHROPIC_API_KEY` の設定と superuser の昇格)・「開発用」メニューの扱い | 58 |

- **E2E**(#36): Phase 59 で既存を含めた全 E2E を流す。Phase 52 は文書の生成の後の流れ(自己診断)を、54 は再生成とチャットを変えるので、既存の E2E(文書の生成・段階の承認)が壊れうる。E2E は偽 LLM で流すので、レビューも偽 LLM が返す。
- **画面確認**(#37 の運用注記): Phase 53・54・57 の画面確認は「未消化の申し送り」に積み、Phase 58 と Phase 59 の本番確認でまとめて行ってよい。ただし 53 は新しい種類の画面なので、操作感は Phase の直後にユーザーが確かめる(デモで流れは決めてある)。
- **効果測定を E2E・デプロイの前に置く理由**: ステージ6・7 と同じ。数字が足りなければ指示や区切りを直すので、その後に E2E の期待とデプロイの手順を固める。
- **実 LLM の費用**: 52〜54 の確認と 58 の測定で Anthropic を呼ぶ。51-1 の測定(約 $3)と同じ程度を見込む。

- 単体テストの仕様(今の手順書のテスト観点のまま)。
