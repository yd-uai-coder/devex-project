## 1. レビューの指示(`app/review/prompt.py`)

責務: レビューの LLM に渡す指示と観点の表を組み立てる(純粋関数。Phase 52)。

[58-1](./Phase-58-1.md) で落ちた型(結び付けの誤り・任意の未決の観点・制約条件・フロントエンドのタスク)を、**題材の答えでなく観点として**足した。

```python
# app/review/prompt.py(REVIEW_SYSTEM_PROMPT の抜粋)
1. 要件 → 設計の追跡: Must の機能要件と非機能要件(…)と制約条件(外部サービスの上限など)が、…
7. ヒアリング: …「未決」の観点は、必須でなくても、設計や計画を決めるのに要るなら挙げる。…
8. 対応の正しさ: 画面・API・タスクの「要件」の欄や付録の対応表が、その要件を実際に満たす
   画面・API・タスクを指しているか(関係の無い要件が結ばれていないか)
## 書き方
- 件数を絞らない。上の観点を1つずつ確かめ、軽微なものも含めて見つけたものはすべて挙げる
```

```python
# app/review/prompt.py(build_points_table)
required = "必須" if is_required(d.key, scale) else "任意"   # 空欄だと「未決」が読まれにくい
```

- 非自明な判断: **「件数を絞らない」が一番効いた**と見ている。Phase 52 で「書かれていないこと」(ヒアリングの指摘)を足したら、別の観点の指摘が押し出された(58-1)。モデルは1回の件数をおおよそ決めるので、観点を足すときは件数の上限を外す言い方を一緒に足す。
- 費用: 出力が 1.4〜1.8倍、1回の費用が 3〜4割増えた(簡易の4文書 $0.10〜0.14、段階7 $0.16〜0.19)。上限(`REVIEW_MAX_TOKENS` 16000・タイムアウト 180 秒)には余裕がある(最大 11.7k・85 秒)。設定は変えていない。
- 効果: S 15.3 → 17.7、D 7.7 → 10.0、detailed-full 19.0 → 22.0(51-1 の Sonnet 16.7・9.0・20.3 を上回った)。

## 2. テスト仕様書の言語の規則(`app/documents/test_spec/drafting.py`)

責務: テスト仕様書の下書きの指示と入力を組み立てる(純粋関数。Phase 56)。

```python
# app/documents/test_spec/drafting.py(SYSTEM_PROMPT の冒頭)
"結合テスト(API 単位)と総合テスト(画面の流れ・非機能)のテスト仕様書を書きます。\n"
"文章(対象・範囲外・環境・完了条件・前提・手順・期待結果・design_gap)はすべて日本語で書く。"
"英語の文にしない(API のパス・項目名・値はそのまま)。\n"
"規則:\n"
```

- 非自明な判断: 規則の最後の1行「日本語で書く」は、必要なテストが 54行ある詳細の回で効かず、63欄中60欄が英語になった。規則を一覧の前に移し、どの欄かを名指しした。直した後の2回は0件。簡易(22〜53件)は直す前から0件だった。

## 3. 申し送りの判断

| 申し送り | 判断 | 根拠 |
|---|---|---|
| プロンプトキャッシュ | **入れない** | 測定の 24本・通しの 7本とも `cache_read` 0。同じ前置き(指示 約 2.5k トークン)が5分以内に繰り返されるのは、同じ区切りを続けて流し直すときだけ。入れても1回 $0.005 未満しか減らない |
| 「直ったか」の精度・使い方 | **今のまま(記録して superuser のパネルに小さく出す)**。「いいえ・一部・自信なし は Sonnet で確かめる」は入れない | 隠して判定した10件で完全一致 8件・二択では10件一致。食い違いは「一部 / 直っていない」の境だけで、Sonnet で確かめても人とも揺れる境 |
| 前の回で採用した指摘が積み上がる・段階の写しの大きさ・聞き直しのあとの再生成は利用者が押す | 今のまま | 通しの2本では困る量にならなかった(採用した指摘は最大8件、段階の区切りの入力は 36〜40k トークン) |
| 「設計に無い」とレビューの指摘の結び付け | **しない** | 仕様書の design_gap は「値の未決」、レビューは「振る舞いの抜け」を拾い、重なりが小さい([58-4](./Phase-58-4.md)) |
| スキーマの単位を計画の生成で作らせる | **推奨: 入れる(段階7)。ユーザーの判断待ち** | 指示の前 29本中 17本、新しい詳細でも1本。生成の指示を変えると今までの測定と比べにくくなる |
| テストのファイルの指示の効果 | 効いた(61% → 38%)。残りは申し送りのまま | |
| 依存の判定の除外が広すぎないか | 問題なし | 新しい2本で誤検知・見落としとも見つからない |
| 「日本語で書く」の効果 | 直した(上の2) | |
| ヒアリングの判定の規則(D-NAT-1) | 効果あり(と見られる) | 2本とも問いがアクセス制御を含み、要件に入った([58-2](./Phase-58-2.md)) |
