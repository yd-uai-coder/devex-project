## 結果

| | 正解例 | 当たり | 落としたものの型 |
|---|---:|---:|---|
| 簡易 33fdda56 | 17 | 12 | 他人のデータ・AI で生成する・失敗のあとやり直せる・献立1件の削除・画面のエラー表示 |
| 詳細 86a37228 | 38 | 28 | {id} の 401・失敗で保存しない・LLM の上限超過・再生成・直近3件の境界・**コピー・ダウンロード**・版の切り替え・サマリと修正依頼・画面の空送信・回数上限の表示 |

- **API ごとの正常・異常・境界と、`{id}` の API の他人のリソースは、必要なテストの一覧どおりにそろう**。NFR も1件ずつある。期待結果の誤りは見つからない。
- **落ちるのは「要件の中身」と「画面の操作」**。予想どおり、コピー・ダウンロード(FR-007)のように要件が API に結ばれていても中身を確かめないものが、簡易 3件・詳細 5件あった。失敗の要件(FR-002・FR-009)は「500 が返る」だけで「保存されない・やり直せる」を確かめない。
- **design_gap は「値が決まっていない」を拾い、「振る舞いが設計に無い」を拾わない**。後者はレビューが拾う型。→ 「設計に無い」とレビューの指摘の結び付けはしない(役割を分ける)。
- 新しい生成で見えた一覧の穴: チャットの送信が `session_id` を本文で受けると、他人のセッションのテストが一覧に入らない(一覧はパスの `{id}` だけを見る。申し送り)。
