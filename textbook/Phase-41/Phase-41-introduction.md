# Phase 41 導入: ステージ7(変更影響分析・変更管理)着手 ── 要件定義フェーズ

## 目的

ステージ6(ヒアリング改良 + 上流の構造化、Phase 33〜40)の完了後、次のステージとして「変更影響分析・変更管理」を始める。構想は [ロードマップ](../../appendix/concept-history.md#roadmap) のステージ7にある。Phase 41 は、[Phase 25](../Phase-25/Phase-25-introduction.md)・[Phase 33](../Phase-33/Phase-33-introduction.md) と同じく、実装に入る前の要件定義フェーズとして次を行う。

- 今の陳腐化(段階単位)を、決まった変更シナリオで測る(ベースライン。[41-1](./Phase-41-1.md))
- スコープの確認と仕様診断(#28)・決定と、Phase 40 の申し送りの1件ずつの判断([41-2](./Phase-41-2.md))
- 変更の影響の見本(md)と、画面のデモ([41-3](./Phase-41-3.md))
- 決定事項の `docs/*.md` への反映([41-4](./Phase-41-4.md))
- ステージ7の実装計画(Phase 42〜50 の一覧・成果物・依存・未確定事項)([41-5](./Phase-41-5.md))

本体機能(要素のグラフ・承認時の写しと要素単位の陳腐化・影響の画面など)の実装は Phase 42 以降で行う。

## モード宣言(#21)・E2E の宣言(#36)

自動実装モード: **on**(AI が本体へ実装し、`textbook/samples/` も同じ内容で作る)。この Phase で本体に入れたのは、devex-ui のデモページだけ。devex-api は変えていない。

E2E: この Phase では流さない(画面の流れを変えないため)。ステージ7の E2E は Phase 50 で既存を含めて全部流す([41-5](./Phase-41-5.md))。

## 着手時の相談で決めたこと

詳細は [`q_a.md`](../q_a.md) の「Phase 41 開始時」を参照。

1. **自動実装モード**: on(推奨どおり)。
2. **ものさし**: 変更シナリオで測る(推奨どおり)。効果測定にも使う。
3. **見本**: md の見本と画面のデモの両方(推奨どおり)。
4. **Phase 40 の申し送り**: 仕様診断の入力として1件ずつ範囲を決める(推奨どおり。ステージ6の振り返り 10.4 の AI 所見)。

仕様診断の決定(10項目と申し送り)は [41-2](./Phase-41-2.md)。推奨と違った選択は5つ(LLM を使わない・簡易モードの文書も model 化・置き場はデモを見てから・写しは直前の1件だけ・L2 等と段階3・5 の書き落としもステージ7に入れる)。

Claude の判断(計画の承認で確定、または作業中):

- ベースラインは外部の API を呼ばず、ステージ6の効果測定の生成物で測る(生成をしない変更の分析なので、実 LLM は要らない)。今の仕組みの判定は本体の `derive_states` をそのまま呼ぶ。
- 4つ目の方式「処理を軸(試案)」は、グラフ(直接)・(全部)の結果を見てから足した。合わせ込みを確かめるため、41-2 の決定の後・実装の前に N1〜N4 を決めて正解を付け、同じ傾向であることを確かめた([41-1](./Phase-41-1.md))。
- デモは決まった形(パネルと各表の印の両方)で作り、置き場の決定(41-2 決定8)の材料にした。
- ステージ6の完了時にユーザーが本体から外したデモのルートとメニューを、samples からも外した(#21。[41-3](./Phase-41-3.md))。

## Phase 完了チェック(#22)

設問は Phase の要点の要約(回答は求めない)。

1. 今の陳腐化は見落としが少ないのに、なぜ変えるのか。示した要素の87%が見直し不要だったことと、同じ段階の中の依存が見えないことから説明できるか。

4. 改名は直接の参照元だけに伝えるのはなぜか。内容の変更との違いから説明できるか。
5. 試案の後に N1〜N4 を決めて測ったのはなぜか。正解を見てから作った規則の数字を、そのまま信じられない理由から説明できるか。
