| 49 | 効果測定 | [ベースライン](../../appendix/stage7-baseline/README.md) と同じシナリオ(S1〜S8・N1〜N4)を、実装した仕組みで測る。47 はステージ6のペルソナで実 LLM を複数回流し、L2 等が聞けたかとゆらぎの幅を数える。48 は段階3・5 の検証の件数 | 42〜48 |
| 50 | 統合/E2E・デプロイでの確認 | 偽 LLM の契約テスト(写し・差分・影響)・既存を含めた全 E2E(#36)・マイグレーションの往復・本番反映の手順(`OPERATIONS.md` 10.4) | 49 |

- **E2E**(#36): Phase 50 で既存を含めた全 E2E を流す。Phase 43・44 は段階の承認と作業領域を、45 は簡易モードの文書の生成を変えるので、既存の E2E(段階の承認・文書の生成の流れ)が壊れうる。
- **画面確認**(#37 の運用注記): Phase 44・46・47 の画面確認は「未消化の申し送り」に積み、Phase 49(効果測定)と Phase 50 の本番確認でまとめて行ってよい。ただし 44 は新しい種類の画面なので、操作感は Phase の直後にユーザーが確かめる(ステージ6の振り返り R2。デモで流れは決めてある)。
- **効果測定を E2E・デプロイの前に置く理由**: ステージ6と同じ。数字が足りなければ規則やプロンプトを直すので、その後に E2E の期待とデプロイの手順を固める。
- **順序**: 42〜44(詳細設計モードの影響)を先に通し、45・46(簡易モード)を続ける。47・48 は他と独立で、42〜46 の間に挟んでもよい(着手時に決める)。
