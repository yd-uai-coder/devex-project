## 1. 題材(決定的、DB も LLM も使わない)

題材は ステージ7 の効果測定の simple-2 の実装手順書(`stages/stage8.json`)と4文書の md(model の無い版なので md の解析の経路)。ステージ8の (e) で Sonnet に渡した `simple-procedure` と同じもの。

| 正解表 | 内容 | 足した検証の結果 |
|---|---|---|
| PR-1(最重要) | どの単位もモデル・マイグレーションを作らない。5つのテーブルがどこでも作られない | `NO_SCHEMA_UNIT` 最重要・直す先は内部設計書(モジュール一覧にスキーマの行が無い)。5テーブルを列挙 |
| PR-3(軽微) | M-01-T01・M-02-T01・M-03-T02 はテスト観点があるのにテストのファイルが無い | `NO_TEST_FILE` 軽微 × 3(同じ3単位) |
| PR-5(中程度) | `auth.py`(M-02-T01)と `chat_graph.py`(M-03-T01)の依存先 `ai_service.py` は M-03-T02 で作る | `DEPENDENCY_BUILT_LATER` 中程度 × 2(同じ2件、作り手 M-03-T02) |

3件とも正解表どおりに当たり、ほかの新しい指摘は出なかった。(e) の Sonnet は PR-3・PR-5 を6回とも当てず、PR-1 は6回中5回当てていた(`results.md` の simple-procedure)。

## 2. dev の DB(読み取りだけ)

段階8の model を持つ 28 プロジェクトで、`DesignStageService.list_stages` の段階8の指摘を数えた(トランザクションは rollback)。

| 指摘 | 初めの判定 | 除くものを足した後 |
|---|---|---|
| `NO_TEST_FILE` | 78 | 78 |
| `NO_SCHEMA_UNIT` | 16 | 16 |
| `DEPENDENCY_BUILT_LATER` | 14 | 2 |
| `TABLE_WITHOUT_UNIT` | 11 | 2 |

初めの判定で見つけた誤検知と、足した除外([55-1](./Phase-55-1.md) の表):

- **依存する側を後の単位でつなぎ直す**(`f5a0ba0a`、詳細): `app/api/projects.py` を M-02-T01 で作り、後の単位がサービス(`chat.py` など)を足すたびに `projects.py` も変更している。依存先を作る単位(か後の単位)が依存する側のファイルも変更するなら見ない。
- **外部のライブラリが層の行に当たる**(`16e995b3`、簡易): 依存先 `FastAPI` が、層の行 `backend/app/*` の `*` に当たっていた。`*` 以外の区切りで当たったときだけ、行を指すとした。
- **まとめたスキーマのファイル**(`16e995b3`、簡易): `backend/app/models/orm.py`(責務「PostgreSQL のテーブル構造に対応する ORM モデル」)にはテーブル名が出ず、4テーブルが「作る単位が無い」になった。名前の出ないスキーマのファイルがあれば、全テーブルを作るとみなした。

残ったもの:

- `DEPENDENCY_BUILT_LATER` 2件は `fd8878ea`(simple-2 の元のプロジェクト)の PR-5 と同じ2件。
- `TABLE_WITHOUT_UNIT` 2件は、テスト用に足した `new_table`・`new_table2`(どの単位も作らない。正しい指摘)。
- `NO_TEST_FILE` 78件・`NO_SCHEMA_UNIT` 16件は、今までの生成物がテストのファイルもスキーマのファイルも持たないことが多いため(PR-1・PR-3 と同じ形)。テストのファイルは生成の指示に1行足した([55-2](./Phase-55-2.md))。スキーマのファイルは、実装計画書・段階7の生成の指示の側の問題で、この Phase では変えない(申し送り)。
