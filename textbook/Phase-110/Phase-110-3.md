## 10.8節の要点

- **マイグレーションは20本**(ステージ11 の9本 + ステージ12 の5本 + ステージ13 の6本)。head は `a9c2e4f6b318`。依存は増えない。
- **共有リンクの回数の上限**(`SHARE_RATE_LIMIT_PER_IP_PER_HOUR`・`SHARE_WRITE_RATE_LIMIT_PER_IP_PER_HOUR`)は、本番の `.env` に置かず既定の 60・20 を使う。開発用の compose だけが E2E のために 1000 にしている。
- **公開の入口**: `/share/<トークン>` はログインが要らない。反映のときに、本番の devex-ui のドメインで開け、API の `/api/v1/share/…` が nginx を通って届くことを確かめる(Phase 108 の申し送り)。
- **反映の後に変わって見えるもの**(マイグレーションではない): 説明書の md の変化で以前の要約がすべて「古い」になる(Phase 101)/ 確認事項の推測の利用者のキーは一覧を開いたときに付け直る(Phase 105)/ 巡回で消えた版の戻しは、反映より前に消えた分は出ない(Phase 106)。
- **ロールバック**: コードはステージ12 の版に戻せる(ステージ13 の表と列を読まない。列は NULL 可)。共有リンクの URL を送ったクライアントは開けなくなる。マイグレーションも戻すと、選択肢・下書き・共有リンク・コメント・判断の出どころ・確認事項の戻しの記録・消えた版の戻しの写しが消える。
- **確認の表**: 規模・選択肢(下書き 約 $0.002)・共有リンクの閲覧(ログインしていないブラウザ、スマートフォンの幅も)・コメントと合意・止まる / 取り消し・確認事項の戻し・段階の参照の切れ・起点と束の CR。追加の費用は 約 $0.02。

## マイグレーションの往復の確認

開発 DB を別のデータベース(`devex_rt`)に `pg_dump` で複製した。backend のコンテナで `DATABASE_URL` だけを複製に向け、`alembic downgrade ee299cd210b8` → `upgrade head` を2往復した(行き先を指定。相対の指定はしない)。使い終わったら複製は消した。開発 DB は触っていない(head・共有リンクの数が変わらないことを確かめた)。

| 時点 | head | 既存の表(利用者・プロジェクト・文書の版・段階・束・CR・合意の記録・確認事項) | ステージ13 の表と列 | 共有リンク・コメント・案のある CR |
|---|---|---|---|---|
| 前 | `a9c2e4f6b318` | 281・213・1043・444・42・20・464・25 | 4表・5列 | 6・2・2 |
| downgrade | `ee299cd210b8` | 同じ | 0 | ── |
| upgrade | `a9c2e4f6b318` | 同じ | 4表・5列 | 0・0・0 |
| 2回目(同じ) | 同じ | 同じ | 同じ | 同じ |

- 6本とも、downgrade・upgrade で `Running …` が出て、エラーは無かった。
