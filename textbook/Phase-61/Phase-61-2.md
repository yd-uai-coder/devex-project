## 書き方の判断

- **まだ決まっていないことは「着手時に決める」と書く**: エラーコードの名前・メールとパスワードの変更の API の形・カタログの取得の API・モデルごとのタイムアウトは、各 Phase の未確定事項([61-3](./Phase-61-3.md))に回した。仕様書に仮の名前を書くと、実装で変わったときに直し漏れるため。
- **今の `users` テーブルの表は直さない**: 表は MVP の時点のまま(`password_hash` の名前・`full_name` が無いなど)で、実際の列とずれている。全面の書き直しは #17(b) の「駆動する消費者が無い遡及の整理」に当たるので、改名の注記だけを足した。
- **選べるモデルを外部設計書に書く**: 画面の選択肢そのものなので、外部設計に置いた(実体は API 側のカタログ)。終了の告知・新しいモデルで改める前提を添えた。
